# Nowen Note Lite

> 移动端极简客户端。与 Nowen Note 服务端**共用同一套后端与登录**，
> 但不包含本地优先 / 离线同步 / 插件 / 思维导图等重功能。
> UI 采用 **iOS 26 液态玻璃（Liquid Glass）** 设计语言。

**当前进度：P0 + P1 + P2 + P3 全部完成**
（登录含 2FA、笔记浏览与**编辑**、全局搜索、待办、日记、液态玻璃 UI）
**P5 已加：笔记流视图切换（仅看笔记 / 文件夹排布）。剩下的只有 P4 打包 APK。**

---

## 它是什么 / 不是什么

| ✅ 是 | ❌ 不是（刻意的） |
|---|---|
| 底部 5 tab：笔记 / 日记说说 / 待办 / 全局搜索 / 设置 | 不是主 App 的功能子集拷贝 |
| **笔记页默认扁平列表，可切「文件夹排布」**（点开就是那一篇） | 没有独立的三级导航（层级只在文件夹视图里展开） |
| 液态玻璃 UI + **圆角悬浮导航胶囊** | 没有本地优先运行时 |
| **Markdown / HTML 笔记可编辑**（带版本冲突保护与草稿兜底） | 富文本笔记只读 |
| 极小的首屏（**98.7 KB gzip**，主 App 约 1.6 MB） | 没有 Sync V2 / 离线队列 |
| 只依赖**已文档化**的服务端 API | 没有插件生态、协同、分享、思维导图 |
| 复用官方 `@nowen/sdk`（MIT） | 不是 fork 主项目前端 |

```bash
npm install

# 方式一：连你自己的 Nowen 服务端
NOWEN_LITE_BACKEND=http://127.0.0.1:3002 npm run dev

# 方式二：连本地 mock（不需要账号，用于跑 UI 测试）
node scripts/mock-api.mjs 3999 &
NOWEN_LITE_BACKEND=http://127.0.0.1:3999 npm run dev
```

打开 `http://127.0.0.1:5174`。手机测试：同一局域网访问 `http://<NAS-IP>:5174`。

> **完全不需要改服务端的 `CORS_ORIGINS`**，生产容器一行都不用动。

## 关键设计决定

### 1. 液态玻璃：折射 + 高光 + 悬浮

三件套缺一不可（代码在 `src/styles.css` 顶部的 `.glass`）：

```css
backdrop-filter: saturate(180%) blur(22px);                 /* 折射 */
box-shadow: inset 0 1px 0 rgba(255, 255, 255, 0.95);        /* 顶边高光 */
.glass::before { background: linear-gradient(158deg, …) }   /* 斜向镜面光泽 */
```

**⚠️ 性能铁律（这条最重要）**：
`backdrop-filter` 很贵，**只用在固定的少数几层** —— 顶栏、悬浮导航、搜索框、卡片壳。
**绝不用在列表的每一行**，否则滚动必掉帧。
`verify-ui.mjs` 里有一条断言专门守这个：`.list-item` 的 `backdrop-filter` 必须是 `none`。

### 2. 内容渲染：三种格式共用一条管线

你库里的真实分布（实测）：

| 格式 | 条数 | 占比 | 处理方式 |
|---|---|---|---|
| `html` | 1295 | 69.6% | DOMPurify 消毒后直接渲染 |
| `markdown` | 521 | 28.0% | `marked` → DOMPurify |
| `tiptap-json` | 11 | 0.6% | **自写递归渲染器**（约 60 行） |

> 为了 11 条笔记引入整套 Tiptap（几百 KB）不划算。
> **未知节点类型退化为渲染其子节点**，宁可样式缺失也不白屏。

### 3. 两级搜索，分工明确

| 位置 | 数据来源 | 特点 |
|---|---|---|
| 笔记列表顶部 | **本地过滤**（标题 + 摘要） | 零延迟，打字即出 |
| 全局搜索 tab | **服务端 FTS5** | 跨全部笔记本、能搜正文 |

> 手机上打字时的即时反馈比省流量重要得多，所以笔记本内用本地过滤。

### 4. 编辑：为什么用原生 textarea 而不是 CodeMirror

| | textarea | CodeMirror 6 |
|---|---|---|
| 中文输入法 | ✅ 走浏览器原生输入栈，最稳 | ⚠️ 自管输入事件，Android/iOS 上 IME 组合态易被打断 |
| 体积 | ✅ 0 依赖 | ❌ 基础包就上百 KB |
| 语法高亮 | ❌ 没有 | ✅ |

手机上本来就是「大段打字」为主，**输入稳定性 > 语法高亮**。
高亮的缺失用「Markdown 工具栏 + 一键预览」来补。

### 5. 两个被真实数据打脸的地方

**① `noteCount` 是递归的，不能直接相加。**
服务端用 `WITH RECURSIVE nb_tree` 汇总，父笔记本的计数**已经包含子孙笔记本**。
所以「把所有可见笔记本的 noteCount 相加」会把同一批笔记算两遍。
要算总可见笔记数，只能加**可见子树里最顶层**那些（`lib/notebookTree.ts::countVisibleNotes`）。

**② API 返回的是「平铺数组 + parentId」，不是嵌套树。**
`backend/src/routes/notebooks.ts` 直接 `return c.json(rows)`。
我最初的 mock 返回的是嵌套 `children` —— **形状和真实服务端不一致**，
等于这条路径一直没被测到。现在 mock 已改成平铺，并额外造了 11 个空笔记本，
用来覆盖「笔记本搜索」「一键隐藏空笔记本」这两条只有在上百个笔记本时才用得上的路径。

**③ 上百个笔记本是常态，不是异常。**
实测你的库：**166 个未删除笔记本**（另有 15 个软删除），
其中 **144 个只有 ≤2 篇笔记、32 个全空**；
而 **3 个笔记本就装了 1438 篇（占 81%）** —— 最大那个是「小米云笔记（2014-2021）」，
1297 篇，是小米云笔记批量导入按来源拆出来的。
所以选择器和设置页都必须有**搜索 + 按笔记数排序**，否则根本没法用。

### 6. 「文件夹排布」为什么只到文件夹层面

两种排布共用**同一份**「隐藏 + 关键词」过滤结果，差别只在怎么组织：

| 视图 | 回答的问题 |
|---|---|
| **仅看笔记** | 「最近写了什么」（全部笔记平铺，置顶在前） |
| **文件夹排布** | 「我的笔记都放在哪些文件夹里」（**只显示文件夹，不列笔记**） |

三条刻意的规则：
1. **展开只出子文件夹，绝不列笔记** —— 否则上百个文件夹一展开就是一屏笔记，
   而「按时间看笔记」本来就是「仅看笔记」的活。
2. **默认全部收起**（展开名单存 localStorage，记的都是例外）
   —— 实测你的库有 166 个笔记本，默认全展开等于刷屏。
3. **点整行 = 进文件夹**（切到「仅看笔记」并只看它**含子孙**），顶部出现可一键清除的范围提示。
   箭头只管展开/收起 —— 两者分开，避免「想展开却进了文件夹」的误触。

> 空文件夹会被**剪掉**（实测有 32 个全是导入产生的中转壳），
> 孤儿笔记（`notebookId` 指向不存在的笔记本）兜到「未归类」，两个视图的条数因此永远一致。

### 7. 说说配图：为什么要自己删「悬空附件」

上传走 `POST /api/diary/attachments`（multipart），**上传成功的附件此时 `diaryId` 是 NULL**，
要等发布说说时随 `media` 一起提交才算绑定。于是有三种「传了但没发」的情况必须收拾：

| 场景 | 处理 |
|---|---|
| 在编辑器里点某张图的 × | 立刻 `DELETE /api/diary/attachments/<id>` |
| 点右上角 × 放弃整篇 | 把已上传的**全部**悬空附件一起删掉 |
| 直接杀掉 App | 收拾不了，只能由服务端兜底 —— **这是已知的残留** |

⚠️ 不做这一步的话，用户每犹豫一次就在服务端留一张永远没人认领的图。
测试里是**真的去请求那张已删的图并断言 404** 来验证的 —— 只断言「界面上少了一个」不够。

### 8. 深色模式：只换 token，不碰组件

整套主题是**一层 CSS 变量**：组件一律引用 `var(--x)`，深色只是把同一批变量换成另一组值
（`[data-theme="dark"]`）。新增组件只要用变量，就自动同时支持深浅色。

三条刻意的决定：

1. **「跟随系统」在 JS 里 resolve，不写 CSS 媒体查询。**
   用媒体查询的话深色 token 得写两遍（`[data-theme=dark]` 和
   `@media (prefers-color-scheme: dark) [data-theme=auto]`），两份迟早漂移。
   这里统一解析成 `data-theme="light" | "dark"`，深色 token 只写一份，
   系统切换时用 `matchMedia` 监听、**不用刷新**就跟着变。

2. **首帧不能闪白。** `index.html` 里有一段内联脚本，在 CSS 生效前就把主题定下来。
   它和 `lib/theme.ts` 是**同一套逻辑的两份实现** —— 故意保留，因为走 JS bundle
   就一定会先渲染一帧浅色。⚠️ 改键名/取值时两处必须同步（两边的注释都写了这句）。

3. **顺手改 `<meta name="theme-color">`**，否则手机上浏览器状态栏会在深色页面顶上留一条白边。

> ⚠️ **踩过的坑（值得记）**：把散落的颜色字面量批量替换成 token 时，
> 替换**把 token 自己的定义也替换掉了** —— 产生 `--page-base: var(--page-base)` 这种自引用，
> 变量在计算时取不到值 → 背景直接变透明。19 个 token 中招，而**深色看着正常**
> （深色块里重新定义了具体值），所以只截图看深色的话完全发现不了。
> 教训：① **批量替换千万不要覆盖定义这些字面量的文件本身**；
> ② 断言要量化到「**底色真的够深吗**」，只断言 `data-theme === "dark"` 等于没测；
> ③ 深浅两套都要看。

### 9. ⚠️ 服务端时间是**裸 UTC** —— 两个因此踩出来的坑

服务端返回的时间形如 `"2026-10-07 08:31:30"`：**是 UTC，但不带任何时区标记**。
而 JS 的 `new Date("2026-10-07 08:31:30")` 会按**本地时间**解析（规范如此）——
东八区下所有时间偏 8 小时，**刚建好的笔记显示成「9 小时前」**。

现在全 App 只有 `lib/time.ts::parseServerTime` 一份解析（补 `Z` 再交给 Date），
需要展示服务端时间的地方一律走它。

设置页里有「**时区自检**」：显示本机时区、UTC 偏移、本机时间、UTC 时间。
时间显示一旦不对，先看这一栏 —— 能立刻区分「客户端解析错了」还是「设备时区不对」，
不用再靠猜。

**两个坑都值得单独记：**

**① 同一份数据两套解析，必然错一套。**
说说那边自己写了解析（补了 Z，是对的），笔记列表那边直接 `new Date()`（错的）。
只要两处并存，就一定会有一处是错的 —— 所以这次把它们合并成一份。

**② mock 的格式和真实服务端不一致，等于没测。**
mock 早期返回 `toISOString()`（带 Z），客户端不补 Z 也解析得对 → 这个 bug
在 194 条断言里**完全看不见**，一上真机就露。
> 同一个病这轮犯了**两次**：另一次是 `POST /api/diary/` 的**尾斜杠** ——
> 真实端点不带斜杠（带则 404），而 mock「两种都收」，把客户端的 bug 养了过去。
> **mock 必须逐字复刻真实契约（包括它有多严格），否则它验证的是 mock 自己。**

### 10. 笔记为什么是扁平的（以及后来又加的「文件夹排布」）

旧结构是「笔记本列表 → 笔记列表 → 笔记」三级 —— 手机上每看一篇要点三层。
现在 `#/notes` **默认直接平铺全部笔记**（服务端 `GET /api/notes` 不带 `notebookId`
时会返回该用户的全部个人笔记），点一条就是那一篇。

笔记本没有消失，只是**降级成了次要信息**：
- 列表副行里带一个笔记本名
- 「设置 · 笔记展示」决定哪些笔记本的笔记要出现在流里

> 偏好存 **localStorage**（`lib/notebookPrefs.ts`），且存的是**隐藏名单** ——
> 这样以后新建的笔记本默认就是可见的，不会出现「新笔记莫名其妙不显示」。
> 另外设置页写入后会**广播事件**，笔记流订阅后立刻刷新
> （两个 tab 的组件同时存在，只靠挂载时读一次会导致「改了设置没反应」）。

### 6.1 视图切换：仅看笔记 / 文件夹排布

搜索框**下方**一个玻璃分段控件，两个视图看的是**同一份数据、同一套过滤**
（隐藏名单 + 关键词），所以来回切不会出现"条数变了"的错觉。

| 视图 | 排布 | 什么时候用 |
|---|---|---|
| **仅看笔记**（默认） | 全部笔记按 `updatedAt` 倒序，置顶在前；笔记本名只在副行 | 日常翻最近写的 |
| **文件夹排布** | 按笔记本层级分组，可展开折叠；父文件夹显示**含子孙**的计数 | 在一千多篇里找"那一本里的东西" |

**默认仍是扁平**：这是刻意保留的 —— 折叠状态下进来会看不到任何笔记，像坏了。

四个实现上的取舍：

1. **折叠 = 不渲染，不是 CSS 隐藏。**
   实测最大的笔记本有 **1291 篇**。CSS 方案（`grid-template-rows` / `max-height`）
   要保留 1291 个 DOM 节点，滚动和内存都白扛。
   直接不渲染 → 展开时才付成本，而且只付在用户真要看的那个文件夹上。
   **代价是没有高度过渡动画**，只有箭头旋转（`transform`，不触发重排）。这里选择性能。

2. **空笔记本一律剪掉。**
   实测库里有 **32 个全空笔记本**（导入产生的中转壳）。不剪的话 33 行里有 6 行点不开。
   剪枝后还要**重算 depth** —— 父被剪掉、自己顶上来时缩进会跳。

3. **笔记数全部现算，不信服务端的 `noteCount`。**
   那个字段是**递归**的（父本已含子孙，见 §5 与 `lib/notebookTree.ts`）。
   直接用它会让「小米云笔记 1291」和它上面的「归档 1291」看起来像 2582 篇。

4. **孤儿笔记兜到「未归类」。**
   `notebookId` 指向不存在的笔记本时（父本被删/数据异常），
   扁平视图会显示它们，文件夹视图更不能吞 —— 否则两个视图条数对不上。

细节：
- 偏好存 localStorage（`lib/noteViewPrefs.ts`），且折叠存的是**折叠名单** ——
  以后新建的笔记本默认是展开的，不会出现「新建了本却看不到里面的笔记」。
- **双重图标的坑**：名字里自带 emoji 的笔记本（`🗂 10 工作台`）如果再把 `icon` 字段
  （通常是通用 📁）渲染出来，就成了「📁 🗂 10 工作台」。
  规则是名字自带图标时**图标位留空但保留宽度**，这样整列名字仍然对齐。

### 11. 并发保护：绝不静默覆盖

服务端对内容类变更**强制要求 `version`**，不一致返回
`409 { code: "VERSION_CONFLICT", currentVersion }`。Lite 的处理：

- 冲突 → **弹框让用户二选一**，没有任何自动覆盖
- 「载入最新（放弃我的修改）」→ 重新拉取
- 「用我的版本覆盖」→ **先取对方最新 version 再提交**
  （保证是在"知道对方改了什么"的前提下覆盖，而不是拿旧版本硬顶）

另外还有**草稿兜底**：停止输入 500ms 后把草稿写进 localStorage，
切 tab / 接电话 / App 被杀都不会丢；回到编辑器会问「恢复还是丢弃」。

> 一开始想「拦截导航」（hashchange 时把 hash 拉回来 + 弹窗），
> 实测**不可行**：切 tab 会让编辑器组件卸载重挂、状态直接丢失，对话框根本没机会弹出。
> 换成草稿落盘 —— 对手机其实更合适。

### 12. 双 Token 与自动续期（「老是会话失效」的修复）

服务端的 Access Token **只有 15 分钟**，长期登录靠 **30 天的 Refresh Token**。
最初的实现只存了 Access Token、从不续期 —— **每 15 分钟必掉线**。

更麻烦的是 `@nowen/sdk` 在 401 时的处理是：

```ts
if (res.status === 401) { this.token = null; await this.login(); }   // ← 拿占位账号登录，必然失败
```

所以 Lite 的做法是**在 SDK 看到 401 之前就把 token 换好** ——
给 SDK 注入自定义 `fetch`（`src/auth/authedFetch.ts`），两道防线：

| 防线 | 时机 | 做法 |
|---|---|---|
| **主动** | 请求发出前 | 本地解 JWT 的 `exp`，距过期 < 60s 就先续期 → 用户完全无感 |
| **被动** | 真收到 401 | 续期后**重放这次请求**（只重放一次，避免死循环） |

细节：
- **单飞（single-flight）**：并发请求同时发现过期时只发一次 refresh，其余等同一个 Promise
- **refresh 轮换**：服务端会作废旧 refresh token，所以要存新的那个
- **网络错误不清 session**（可能只是暂时断网），只有 refresh 真的被拒（401/403）才清

### 13. 认证自己写，且只用 localStorage

`@nowen/sdk` 的 `login()` 是 private 且只吃 `username/password`，**不支持 2FA**；
而本服务端账号普遍开着 2FA。所以：

```
POST /api/auth/login        → { token }  |  { requires2FA, ticket, username }
POST /api/auth/2fa/verify   → { token }     （ticket 只活 5 分钟）
```

> ⚠️ **绝不复用**主项目的 `rememberLogin.ts` / `mobileLocalFirstRuntime.ts` /
> `accountLoginHistory.ts` —— 那些是 issue #798「启动挂起」的发源地
> （Capacitor 插件 Proxy 被当作 thenable）。Lite 只用 localStorage，没有原生依赖。

## 发现的上游 Bug（`@nowen/sdk`，MIT）

`sdk/` 是 vendored 的官方 SDK，打了 **2 处必要补丁**；
另有 **2 处坏得没法用**，Lite 直接绕开、走 `src/api/rest.ts` 打真实端点。

| # | 问题 | 影响 | 处理 |
|---|---|---|---|
| 1 | `this._fetch = globalThis.fetch` 后以 `this._fetch()` 调用 → `this` 不是 `window` | **浏览器里所有请求必炸**（`Illegal invocation`），Node 里侥幸能过 | 补丁：`globalThis.fetch.bind(globalThis)` |
| 2 | `login()` private 且无 `setToken()` | 无法在外部走完 2FA 后复用数据方法 | 补丁：加 `setToken()` / `getToken()` |
| 3 | **`listDiaries()` 打到不存在的端点** | 请求 `GET /api/diary?month=`，真实端点是 `GET /api/diary/timeline` → **必 404** | Lite 绕开，直连真实端点 |
| 4 | `DiaryEntry` 类型与真实响应对不上 | 声明 `date`/`content`/`weather`，实际是 `createdAt`/`contentText`/`mood` | Lite 自定义类型 |

> 这四条都很适合作为**独立的小 PR** 提给上游（MIT 包、不涉及 UI、改动极小）。
> 其中 #1 最严重 —— 意味着**任何浏览器端使用者都会立刻撞墙**。

## 已知限制

  强行 HTML→Markdown 会有损，可能把剪藏的内容改坏
- 说说**可以配图/配视频**（视频在列表里显示为 🎬 占位，未做内嵌播放）
- 发布后的说说**不能编辑/删除**（服务端接口未接）

### ⚠️ 两个必须知道的坑

1. **不能用 `sqlite3` CLI 直接喂 SQL。** 库里的 `notes_search_ai/ad/au` 三个触发器
   调用了**应用运行时才注册**的自定义函数 `nowen_search_normalize`，
   裸 `sqlite3` 报 `no such function` → 每条 INSERT 都失败（而且**不会回滚**，
   会留下一堆只剩笔记本壳的脏数据）。
   所以 `seed-runner.mjs` 必须在**容器内**跑，并用容器自带的 better-sqlite3
   注册**与应用同一份实现**（直接 require 应用的构建产物 `dist/lib/searchQuery.js`，
   不自己重写，避免两边行为漂移）。

2. **`userId` 必须拼成 SQL 表达式，不能加引号。**
   早期版本把 `(SELECT id FROM users WHERE username='nowen')` 当成字符串插进去，
   结果造出 `userId` 是那串文字的孤儿数据 —— 界面上一个笔记本都看不到。
   runner 里有一条自检专门拦这个（`userId LIKE '(SELECT%'` 直接报错退出）。

### ⚠️ 装进 APK 后必须处理的四件事

WebView 的 origin 是 `https://localhost`，和浏览器里跑完全不是一回事：

| 问题 | 处理 |
|---|---|
| 相对 URL 打到手机本机 | `src/api/rest.ts` 的 `serverUrl()` 统一补成服务端绝对地址（附件/说说图片都过了它） |
| Android 9+ 禁明文 HTTP | `server.cleartext: true` + 清单里显式 `usesCleartextTraffic="true"` |
| WebView(https) 加载 http 资源 | `android.allowMixedContent: true` |
| 首次打开没有服务器地址 | 登录页可填服务器地址（留空＝同源，在 APK 里等于 localhost，**必须填**） |

### ⚠️ 两个构建坑（都踩过）

1. **国内直连 `dl.google.com` 会被 TLS 重置** —— 表现是 `SSLHandshakeException:
   Remote host terminated the handshake`，而同一台机器 `curl` 却是 200。
   已把**阿里云镜像**配到 `settings.gradle` / `build.gradle` 最前面（官方源留作兜底）。
2. **Kotlin 重复类** —— `kotlin-stdlib 1.8.x` 与老的 `kotlin-stdlib-jdk7/jdk8 1.6.x`
   同时存在会 `Duplicate class`。`build.gradle` 里用 `resolutionStrategy` 把 jdk7/jdk8 对齐到 1.8.22。

> 构建环境：`JAVA_HOME=/vol1/nowen-dev/jdk21`、`ANDROID_HOME=/vol1/nowen-dev/android-sdk`、
> `GRADLE_USER_HOME=/vol1/nowen-dev/gradle-home`（`scripts/build-apk.sh` 已经内置）。
