## 各 Phase 关键设计决策（含理由）

**Phase 5 `sync/resolve.ts` + `routes/sync-local.ts`**
- 三方 payload 永久保留，`resolveConflict` 只改状态 → 用户选错可回退
- **保留本机 = 重新入队推送**，而非直接改远端；`baseVersion` 用
  `row.remoteVersion`（服务端当前版本），否则会立刻再判冲突陷入死循环
- 不自动生成"冲突副本"；`forkConflictVersion` 仅在用户显式点击时调用
- `fillRemotePayload` 补齐 push 阶段只拿到版本号的冲突（Engine 在 Pull 时调用）

**Phase 6 `sync/notify.ts`**
- WS 只发 `{type:"sync.changed", sequence}`，不带业务内容 → 无需权限过滤
- 用 `setSyncBroadcaster` 注入而非直接 import realtime → sync 模块能在
  无 WebSocket 环境（CLI/测试/迁移脚本）工作
- 只在 `applied > 0` 时通知，避免空 push 唤醒其他设备

**Phase 7 前端**
- `syncLocalApi.ts` 定义 `SyncV2DisabledError`：404 是默认状态不是错误，
  UI 应静默隐藏同步入口而非弹错误
- `useSyncIndicator.ts` 措辞铁律：本地成功即"已保存"，远端失败只叫
  "等待同步/同步失败"；断网优先于错误（"离线 · 已保存到本机"更准确也更安心）
- 用 15s 轮询而非 WS 推送：指示灯对实时性要求低，不值得维护额外连接

**Phase 8**
- `services/clipper-credential.ts`：只存 SHA-256 摘要，`timingSafeEqual` 比较；
  scopes 解析失败时退回最小集合而非放行全部
- `routes/clipper-local.ts`：`assertLoopback` 在应用层再确认一次
  （出现 `x-forwarded-for` 即拒绝）—— 反代/端口转发可能让 Backend 意外外露
- `electron/clipper-host.js`：Native Messaging 只传"去哪连"，
  **网页内容走 HTTP**（Chrome 单条消息 1MB 上限，带图剪藏必超）
- runtime 文件 0600 权限（含凭据）；`stopBackend` 时清理，
  否则扩展会连到已失效端口长时间等待
- `localChannel.ts` Pending Queue 用 IndexedDB 而非 `chrome.storage.local`
  （后者 5MB 配额，带图剪藏易爆）；失败条目保留并累加 retryCount，永不删除

**Phase 9 `sync/attachments.ts`**
- 单独建表而非给 attachments 加列：后者是所有部署形态共用的热表，
  同步状态只对启用 Sync V2 的客户端有意义
- `promoteLocalAttachments`：关闭同步期间插入的图片状态是 local，
  开启后必须统一转 pending，否则其他设备全是破图
- `remoteOnly=1` 让 UI 显示"正在获取图片"而非破图
- `listPendingUploads` 按 retryCount 升序：避免一个长期失败的大文件
  占住队头把后面小图饿死
- `recoverStuckUploads` 启动复位 uploading（强杀恢复）

**Phase 10 `frontend/src/lib/localRepository.ts`**
- 只做接口 + `setLocalRepository`/`getLocalRepository`；`getLocalRepository`
  返回 null 而非抛错 → 未迁移模块继续走原 api 路径，支持逐模块灰度
- `newLocalId()` 客户端生成 UUID，离线创建不依赖服务器分配

**Phase 11-12 `sync/entities.ts`**
- `assertEntitySyncReady` 强制校验七环节，挡住"只做上传"的半接入
  （这类半接入是同步系统最常见的数据丢失来源）
- `WORKSPACE_OFFLINE_BLOCKERS` 列出 6 项阻塞；
  `isWorkspaceOfflineEditingEnabled()` 恒 false 但保留成函数，
  将来接入时有可测试的开关点

**Phase 13 `sync/legacyCleanup.ts`（清单，不执行）**
- `CLEANUP_PRECONDITIONS` 五项全 false；`assertLegacyCleanupAllowed()` 守卫
- 8 项清理目标各自标注 precondition 与提前删除的后果
