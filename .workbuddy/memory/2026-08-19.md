# 2026-08-19

## Local-first + Optional Sync 改造（release/v1.4.16）

分阶段把 Nowen Note 从 Remote-first 改造为 Local is Primary / Remote is Replica。
本日完成 Phase 0 与 Phase 1，均已 STOP 等待人工验收。

### 架构现状结论（分析 release/v1.4.16 得出）
- Desktop Full：Electron 用 `getFreePort()` 取 127.0.0.1 随机端口 → spawn
  `backend/dist/index.js` 子进程 → 轮询 `/api/health` 就绪 → SQLite 在
  `{userData}/nowen-data/nowen-note.db`。
- serverUrl 注入方式：`mainWindow.loadFile(frontendIndex, { query: { serverUrl } })`，
  renderer 侧 `api.impl.ts` 从 query 读取后落 localStorage `nowen-server-url`。
- Full/Lite 是**两套数据源**：full→localhost，lite→remoteUrl；切换靠
  写 settings.json + `clearWebStorage()` + relaunch。
- 桌面零登录：`ensureLocalAccount()` 用固定用户名 `desktop` +
  `{userData}/.local_account_secret`（32B base64，0600）走本机 /auth/login|register。
- **IndexedDB 是 Cache 而非权威数据**（`localStore.ts` 的 schema 就叫
  `NowenCacheSchema`），`offlineRead.ts` 的 `withFallback` 明确是
  Remote-first + 断网 fallback。
- offlineQueue 基于 localStorage，7 天 MAX_AGE + MAX_RETRY=10，
  超限只标记 blocked 保留副本，不能作为正式 Sync Outbox（无法与业务写入同事务）。
- Offline Sync V1：`/api/offline-sync` 仅 `GET /plan|/snapshot|/changes` +
  `POST /ack`，**纯单向下行**；变更捕获靠 migration v66 的 **DB Trigger**
  写 `offline_sync_changes`，仅覆盖 note / attachment（favorite、note_tags 也
  折算成 note upsert）。
- Clipper（packages/nowen-clipper）直接持 serverUrl + token + refreshToken 访问远端。

### 关键版本号
- 数据库 migration 当前最大版本 **80**（`taskReminderTimezoneMigration`），
  Phase 2 新增迁移必须从 **81** 起，且不得修改已发布迁移。
- 迁移注册在 `backend/src/db/migrations.ts` 的 `MIGRATIONS` 数组（按 version 排序）。

### Phase 0（commit 40419d173）
新增 `backend/src/sync/`：flag / types / constants / errors / context / log / index。
Feature Flag `NOWEN_LOCAL_FIRST_SYNC_V2` 默认关闭。零现有文件改动、无 migration。
- 防回环原语 `context.ts` 用 **AsyncLocalStorage** 而非模块级布尔量：
  异常自动恢复、并发异步写入互不污染、嵌套安全。
- 日志用**白名单**字段而非黑名单脱敏，避免将来加字段时漏脱敏泄漏正文。

liteMigrationStatus；`electron/main.js` 的 targetUrl 改由 runtime 判定。

### 环境坑（重要）
本机 `.git/refs/heads/release/` 子目录会被环境回滚：`git commit` 成功生成
commit 对象，但分支 ref 与 `refs/heads/release/` 目录随即消失，`git update-ref`
报 exit 0 却不落盘。恢复办法：确认 commit 对象与 reflog
（`.git/logs/refs/heads/release/*`）完好后，直接编辑 **`.git/packed-refs`**
写入 `<sha> refs/heads/release/<name>`，该单文件不受影响。每次提交后都要
`git rev-parse HEAD` 校验，必要时更新 packed-refs。

## Phase 2 完成（migration v81）

新增 `backend/src/db/syncV2LocalStateMigration.ts`（version 81，
name `sync-v2-local-state`），注册进 `backend/src/db/migrations.ts` 的 MIGRATIONS。
建 6 表：sync_profiles / sync_devices / sync_state / sync_outbox /
sync_applied_mutations / sync_conflicts。只建表、不写数据、不装触发器。

新增读写层 `backend/src/sync/`：outbox.ts / device.ts / profile.ts / conflict.ts。

关键设计决策（含理由）：
- **entityId 一律不建外键**。删除笔记后 "delete" mutation 必须存活到推送成功，
  加外键会被级联清掉，导致删除永远不同步到其他设备。
- `sync_outbox.profileId` 允许 NULL 且 `ON DELETE SET NULL`：关闭同步期间
  仍记录变更，开启同步后 `listPendingMutations(db, n, profileId)` 会把
  `profileId IS NULL` 的条目一并补传。
- outbox status 只有 pending / inflight / failed，**没有 discarded 终态**；
  `markMutationFailed` 只累加 retryCount，永不删除。
- `withMutation(db, input, write)` 是业务应当使用的入口：用 db.transaction
  把业务写入与 enqueueMutation 包成原子操作，杜绝"内容已改但 mutation 没入队"。
- `recoverInflightMutations()` 启动时把 inflight 复位 pending（强杀恢复）；
  重复推送安全，因为服务端按 mutationId 幂等。
- `advanceSyncState` 用 `MAX(lastSequence, excluded.lastSequence)` 保证游标
  只前进不后退，避免迟到响应导致重复拉取。
- sync_profiles 对 (serverUrl, remoteUserId) 建**部分唯一索引**
  （WHERE remoteUserId IS NOT NULL），同一 NAS 上不同账号可并存。
- `recordConflict` 要求至少有 localPayload 或 remotePayload，否则报错——
  两侧都缺失的冲突无法恢复，等于静默丢数据。
- `resolveConflict` 只改状态不删记录，用户选错后仍能取回另一版本。

顺带修复既存失败测试 `tests/migration-task-version-compatibility.test.ts`：
原断言硬编码 `CURRENT_SCHEMA_VERSION === 77`，v78/79/80 引入时就已失败
（与本次改动无关，已验证移除 v81 后仍报 `80 !== 77`）。改为断言
`>= 77` 且 `MAX(schema_migrations.version) === CURRENT_SCHEMA_VERSION`。

测试：`tests/sync-v2-local-state.test.ts` 32 项 + 契约 17 项 = 49 项通过；
迁移相关 18 项通过；note/notebook/attachment 抽样回归 60 项通过。

## 环境问题（严重，必须知晓）

### 1. better-sqlite3 ABI 不匹配（预先存在）
`backend/node_modules/better-sqlite3/build/Release/better_sqlite3.node` 是为
**Electron（ABI 130）** 编译的，本机 Node 是 22.22.2（ABI 127），
导致**所有** DB 相关后端测试报 ERR_DLOPEN_FAILED（既有测试同样失败，非新引入）。
解决办法（不破坏 Electron 那份）：下载
`better-sqlite3-v11.10.0-node-v127-win32-x64.tar.gz`，把 .node 放到
`node_modules/better-sqlite3/build/better_sqlite3.node`——
`bindings` 的查找顺序里 `build/` 优先于 `build/Release/`，
因此不必替换（且 Release 那份被进程占用无法替换）。
原 Electron 版本已备份到 `/tmp/bs3probe/better_sqlite3.electron-abi130.node.bak`。

### 2. .git 被沙箱回滚（导致提交丢失）
本机环境会回滚 `.git` 下的文件：
- 先是 `refs/heads/release/` 子目录被删（`git update-ref` 报 exit 0 但不落盘），
  当时靠改 `.git/packed-refs` 恢复；
- 随后 **`.git/objects/pack/*.pack` 全部消失，只剩 `.idx`**，
  整个提交历史不可读（`git cat-file` 对任何对象都失败，包括远端基线 dd1931a2d）。

因此 Phase 0（40419d173）、Phase 1（c0829e1e3）的 commit 对象已不可读，
**但工作区所有源码完好**。成果已打包固化到仓库外：
`C:\UGit\nowen-localfirst-phase012.tar.gz`（含 sync/ 全部模块、migration、
settings.js、main.js、4 个测试文件、migrations.ts）。

恢复建议：重新 clone 仓库到干净目录，解包上述 tar.gz 覆盖对应路径后重新提交。
在此环境修复前不要依赖本地 git 历史。
