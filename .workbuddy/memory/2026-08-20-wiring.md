## 关键设计决策（含理由，勿轻易改动）

| 决策 | 理由 |
|---|---|
| 引擎管理放 runtime.ts 而非 index.ts 直接 new | 生命周期由 HTTP 路由里的用户行为驱动，拿不到启动时局部变量；凭据可能晚于启动写入 |
| 启动顺序：崩溃恢复 → reconcile | 反过来引擎会取到仍标记 inflight 的条目 |
| 切换 Profile 先 stop 再 start | 否则两个引擎同时把同一批 Outbox 推向不同服务器 |
| token 存 0600 文件不进 DB | DB 会被备份导出，token 跟着走 = 凭据泄漏；换机恢复后旧 token 已失效 |
| 附件登记用 **DB Trigger**（v84）而非逐点调用 | `INSERT INTO attachments` 有 8+ 处（attachments-core×4、files、folder-sync、url-import、noteDuplicates、noteTemplates），埋点必漏 |
| v84 ON CONFLICT 只补 profileId、不改 status | Pull 先写 remoteOnly=1 状态行，无条件重置会把"远端待下载"误判为"本地待上传"，把空文件推回服务器 |
| 同步徽标与保存指示器**分开组件** | 本地写入=已保存，远端 ACK=已同步。合并后一次网络抖动就显示"保存失败" |
| Clipper 分流点放 `importNote` 内部 | 5 处调用点，改内部一处即全覆盖；工作区剪藏一律走远端（V1 不支持工作区离线） |
| 宿主脚本必须在 **asar 之外**（extraResources） | asar 是虚拟归档，外部进程无法从中 spawn，留在里面剪藏永远唤不起 Desktop |
| ensureHostLauncher 生成 .cmd/.sh + ELECTRON_RUN_AS_NODE | 清单 path 必须可执行，.js 不是；用户机器可能没装 Node |
| 每次启动重新注册清单 | 便携版与 AppImage 路径随目录移动而变 |

## 环境注意事项（反复出现）

1. **git commit 后 ref 不自动推进** —— 需手改 `.git/packed-refs`，SHA 从
   `.git/logs/refs/heads/release/v1.5.0` 尾行取。
2. **`.pack` 文件会被环境清除**（本次未发生，前几次发生过）。每阶段完成
   立即 tar 备份到仓库外。
3. **`git push` 不可用** —— 需交互式凭据。
4. `tests/note-delete-attachments.test.ts` 单文件耗时 ~103 秒，多文件并跑易超时；
   输出极长，`grep` 管道可能返回空，用 `tail` 更可靠。
5. `notebook-transfer-copy.test.ts` 有 2 项**预先存在**的失败
   （`NOTEBOOK_CHILD_SCOPE_MISMATCH`，来自 `runtime/notebook-tree-hardening.ts`），与同步改造无关。
