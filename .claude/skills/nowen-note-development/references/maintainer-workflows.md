# Maintainer 工作流程

只读当前任务章节；共同约束见 [SKILL.md](../SKILL.md)，代码入口与命令见 [开发参考](development-guide.md)。历史 Issue 用于说明场景，不代表当前缺陷状态，无需每次重新获取。

## 1. 用户反馈与 Bug 分析

- 从 Issue 正文、相关评论和日志取得：实际 / 期望行为、客户端与服务端版本、平台、运行模式、升级路径、数据状态及复现步骤。对照正常端 / 异常端和新旧版本。
- 沿真实读写链路确认 ID、账号 / Profile、资源与作用域、权威存储、请求状态和持久化边界。候选根因附证据及区分它们的验证方法，不能把假设写成结论。
- 回归前置状态必须匹配：本地记录缺失、正文为空、正文陈旧、含未同步编辑是不同场景，恢复不能覆盖本地意图。参见 [#829](https://github.com/cropflre/nowen-note/issues/829)。
- 多诉求用“诉求 → 实现证据 → 验证 / 剩余项”逐项核对，延期或不采纳说明原因，例如 [#749](https://github.com/cropflre/nowen-note/issues/749)。交付根因或假设、最小方案和验收条件；仅分析请求到此结束。

## 2. 已授权实施与自审

1. 基于现有公共入口实现最小方案，遵守 API、迁移、组件风格和 i18n；回归验证用户行为或数据不变量。
2. 按调用链选失败路径：断网、401/403、超时 / 5xx、重复请求、迟到响应、再次编辑、重启和切换身份。
3. 区分请求失败与业务失败；超时先核查任务或持久化状态再重试，避免重复写入，例如 [#703](https://github.com/cropflre/nowen-note/issues/703)。多步骤写入验证事务、幂等和失败清理；有创建权限不代表有移动 / 删除权限，例如 [#747](https://github.com/cropflre/nowen-note/issues/747)。
4. 自审 diff 的遗漏入口、竞态、旧数据 / 旧客户端与迁移风险；修正后重跑受影响验证。交付结果、证据与未验证范围。

## 3. 新需求与大型设计

- 明确用户问题、非目标、验收范围；复用已有能力，选择最少交互、清晰命名及必要的空 / 加载 / 错误 / 只读状态，不机械增加设置或抽象。
- 沿模型 / SQLite → API → 前端状态分析权限、同步、历史兼容和导入导出。新增数据类型覆盖创建、保存、重开、同步、导出和备份恢复的适用链路，验证内容语义，例如 [#835 TXT](https://github.com/cropflre/nowen-note/issues/835)。
- 大型设计补充协议 / 格式版本、事务与权威源、冲突、性能、迁移及回滚；加密额外说明威胁模型、密钥生命周期与恢复边界。按核心验收分阶段，不把计划能力写成已支持。

## 4. PR 审核

读取目标分支、当前 diff、相关 Issue / 评论和真实调用者，核对验收。按范围检查类型契约、异常、竞态、事务、同步、性能、权限、XSS 与敏感数据；数据变更提供 PR 模板要求的 DCC 证据。

只报告有证据的可行动问题：严重等级、准确文件 / 行、触发条件、影响及最小修复建议；区分新增问题与既有问题。给出 Approve / Request Changes / Comment 建议和理由；未发现问题仍说明验证缺口。默认交付 Review 草稿，发布遵循已有授权。

## 5. 发布回归与验收

记录 commit、候选产物、客户端 / 服务端版本、OS / 架构、设备和部署方式。按实际变更设计并执行可用检查，不默认全平台全量回归。

| 涉及范围 | 关键断言 |
| --- | --- |
| 编辑 / 数据类型 | 保存、重开、转换后内容语义一致，未保存内容可恢复 |
| 同步 / 权限 / 加密 | 第二设备可读；并发双方保留；跨身份隔离、越权拒绝、明文不泄漏 |
| 附件 / 导入导出 / 迁移 | 引用与文件完整；往返校验；失败保护原数据 |
| AI / 插件 | 授权范围、取消与失败恢复；外发边界、沙箱隔离与产物完整 |
| 桌面 / Docker / 移动包 | 最终产物匹配目标 OS / 架构，依赖可加载；安装、启动、更新保留数据 |

打包检查实际安装包 / 镜像，不能只看源码配置；核查目标平台原生依赖（如 sharp、better-sqlite3）、动态库、图标 / 元数据及启动健康检查。参见 [#860](https://github.com/cropflre/nowen-note/issues/860)、[#744](https://github.com/cropflre/nowen-note/issues/744)。目标系统不可用时，解包检查与目标系统启动验收分别记录。

每项保留“环境与前置状态 / 步骤 / 预期 / 实际 / 证据或阻塞”。区分源码测试、构建、CI、浏览器、安装包、模拟器、真机和生产证据；缺环境标未执行并提供复测步骤。数据丢失、越权、明文泄漏或关键路径失败阻止发布；说明升级和数据回滚限制。

Issue 回复写明已完成范围、真实提交 / 版本、验证限制和升级复测方式；不能用合并到 release 分支代替正式发布证据。

## 6. 隐藏问题与安全审计

沿真实数据与权限流确定范围，使用隔离模拟数据验证；不凭清单臆测缺陷。输出严重等级、证据状态、原因 / 触发条件、影响、位置、修复与验证方法，以及未覆盖范围；“未发现”不是安全保证。

审计本身不授权修复、修改真实数据或创建自动任务；已授权修复的部分继续实施。
