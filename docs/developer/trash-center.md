# 统一回收站

`/trash` 是独立页面，普通 `NoteList` 不再承担恢复、清空和永久删除。`frontend/src/features/trash` 包含统一模型、API 入口、加载 hook 和页面。

## 数据与权限

没有新增回收站存储表。资源 ID、附件引用、Yjs 和 Sync V2 继续保留原生命周期：笔记及轻量表格使用 `notes.isTrashed`；文件夹使用 `notebooks.isDeleted`；脑图使用知识树 Tombstone。列表来自含已删除节点的知识树，并沿用 Tombstone ACL；原位置只展示当前用户有权看到的祖先名称。

后端 `services/trash/trashService.ts` 统一列表、恢复、批量操作和清空。笔记和脑图永久删除适配器同时供旧接口使用，保留附件清理、锁定、权限、Yjs、审计及同步触发器行为。

## 内部 HTTP 接口

所有请求需登录会话，`workspaceId=personal` 或工作区 ID 显式限定空间。API Token 暂不开放混合资源回收站管理，避免绕过既有 Token scope。

- `GET /api/trash?workspaceId=...`：统一元数据及恢复/永久删除能力。
- `POST /api/trash/batch?workspaceId=...`：`{ action: "restore" | "permanent", ids: string[] }`，一次最多 500 个所选知识树节点 ID。
- `DELETE /api/trash?workspaceId=...`：尝试清空当前用户可见的已删除资源。

操作响应为 `succeededIds`、`noteIds`（确认永久删除的笔记 ID）和 `failures`。前端仅清理确认删除笔记的离线写入队列。批量请求可能部分成功，失败项保留并展示原因；无法撤销的操作在提交前提示资源数量。

## 恢复与永久删除

单项恢复的必要祖先链及目录删除 cohort 在同一数据库事务内恢复。选择一个被更早删除的子项时，先恢复必要祖先，再恢复该子项；其他更早删除的兄弟项留在回收站。祖先目录不可见或无恢复权限时，操作失败，不泄露祖先信息。

永久删除所选容器时扩展当前可见的已删除后代，按深度从子项到父项操作。每项独立检查权限；锁定、无权限、活动和隐藏子项不会被 FK 级联误删。容器必须同时满足知识树和原表为空才可物理删除。任何保留子项都会阻止容器删除。数据库空间回收在批次结束执行一次。

当前统一类型为笔记、文件夹、脑图和轻量表格。独立文件管理中的文件未接入本次回收站；含文件节点的容器仍受非空保护。大列表尚无分页/虚拟滚动。

## 回归

`backend/tests/trash-center.test.ts` 覆盖四类资源、路径与删除时间、祖先恢复及 cohort、混合永久删除、锁定内容、空间隔离、显式拒绝、隐藏后代和恢复事务失败。前端 `TrashPage.test.tsx` 覆盖筛选、确认取消、批量、部分失败、加载重试及空间切换；离线队列回归验证仅移除服务端确认的删除。
