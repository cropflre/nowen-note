# Nowen Note Local-first 人工验收清单

> 生成时间：2026-08-21
> 分支：`release/v1.5.0`
> 适用版本：Sync V2（migration v87 ~ v90）
>
> **本清单尚未执行。** 下面每一项都需要你在真实设备上人工确认。
> 自动化测试覆盖的是契约与边界，无法替代真机、真网络、真浏览器的验证。

## 前置准备

- [ ] 准备两台桌面设备（A / B），或一台设备 + 一份独立数据目录
- [ ] 准备一台 Nowen Server（NAS / Docker 均可）
- [ ] 备份当前生产数据目录（`{userData}/nowen-data/`）
- [ ] 确认 Sync V2 默认开启：**不需要**设置 `NOWEN_LOCAL_FIRST_SYNC_V2`
      （如需停用则设为 `0` 或 `false`）
- [ ] 记录服务端 schema 版本（应为 90）

---

## 1. Desktop 本地优先（无服务器）

- [ ] 全新安装，不配置任何服务器 → 能创建笔记本、笔记、标签
- [ ] **完全断网**下创建笔记 → 退出应用 → 重新打开 → 数据完整
- [ ] 断网下编辑笔记正文（Markdown + 富文本）→ 重开后修改仍在
- [ ] 断网下插入图片 → 图片立即显示 → 重开后图片仍能显示
- [ ] 断网下导入 Markdown / 导出为 zip 均正常
- [ ] 断网下全文搜索能命中刚创建的笔记
- [ ] 断网下创建任务、说说、思维导图 → 重开后全部存在
- [ ] 设置页「同步」显示「不同步，仅此设备」
- [ ] 检查 `{userData}/nowen-data/settings.json` → `mode`/`remoteUrl` 字段仍在（向后兼容）

## 2. 首次开启同步（Bootstrap / Reconcile）

### 2.1 本地有数据、服务器为空
- [ ] 本地先建 20+ 篇笔记 → 连接服务器 → 触发对账
- [ ] 对账完成后服务器端能看到全部笔记
- [ ] 本地数据一条不少

### 2.2 本地为空、服务器有数据
- [ ] 全新设备连接已有数据的服务器 → 对账后本地出现全部笔记
- [ ] 附件图片能正常显示（可能需等后台下载完成）

### 2.3 两边都有数据
- [ ] A 设备本地 10 篇、服务器 10 篇（不同 ID）→ 对账后共 20 篇，**无丢失**
- [ ] 标题相同但 ID 不同的两篇笔记 → **并存**，不被合并
- [ ] 同 ID 同内容 → 不产生冲突
- [ ] 同 ID 内容不同 → 进入冲突中心，**两个版本都能查看**

### 2.4 中断与恢复
- [ ] 对账进行中拔网线 → 恢复网络后重试 → 从中断处继续（不重新全量下载）
- [ ] 对账进行中强杀应用 → 重启后能继续对账
- [ ] 对账期间继续编辑笔记 → 对账完成后这些修改也被上传
- [ ] 对账完成后重复触发 → 直接返回，不产生网络请求

## 3. 双向增量同步

- [ ] A 创建笔记 → B 在一分钟内看到（或手动刷新后看到）
- [ ] A 编辑笔记正文 → B 收到更新
- [ ] A 删除笔记 → B 上也消失
- [ ] A 移动笔记到另一笔记本 → B 同步
- [ ] A 加标签 / 取消标签 → B 同步
- [ ] A 收藏 / 取消收藏 → B 同步
- [ ] A 创建任务（含截止日期、优先级）→ B 看到且字段完整
- [ ] A 设置任务提醒 → B 同步；**B 的提醒不受 A 已弹过通知影响**
- [ ] A 发说说（带图）→ B 同步
- [ ] A 编辑思维导图 → B 同步且整份结构完整

## 4. 冲突

- [ ] A、B 同时断网 → 各自修改同一篇笔记 → 都恢复网络
- [ ] 必须出现冲突提示，**不得**有一方修改被静默覆盖
- [ ] 设置页「同步 → 冲突」能看到本机版本、服务器版本与差异
- [ ] 选「保留本机」→ 服务器与另一台设备都变成本机版本
- [ ] 选「保留服务器」→ 本机变成服务器版本
- [ ] 解决冲突后**仍能查看**被放弃的那个版本
- [ ] 重启应用 → 未解决的冲突仍然存在（持久化）
- [ ] 思维导图冲突时整份 data 不被覆盖
- [ ] 冲突解决**不会**在知识树里生成大量「xxx 冲突副本」

## 5. 附件二进制

- [ ] 上传 10 KB 小图 → 立即显示
- [ ] 上传 5 MB 图片 → 立即显示，后台上传
- [ ] 上传 20 MB 文件 → 不阻塞笔记编辑
- [ ] 中文文件名、emoji 文件名、同名文件均正常
- [ ] PDF / ZIP 附件能正常上传下载
- [ ] 上传图片后**立即断网** → 退出重开 → 图片仍能显示
- [ ] 断网期间上传的附件在恢复网络后自动补传
- [ ] B 设备收到 A 的附件（可能先显示"正在获取"再变成图片）
- [ ] 服务端删除附件文件后 B 拉取 → 提示未就绪，**不删除本地记录**
- [ ] 关闭同步期间新增的图片 → 重新开启同步后被补传

## 6. 断网 / 服务器故障 / 授权失效

- [ ] 同步模式下断网 → 编辑正常，状态显示「离线 · 已保存到本机」
- [ ] 断网期间的修改在恢复网络后全部同步（不丢）
- [ ] 停掉服务器 → Desktop 全部本地功能正常
- [ ] 服务器恢复 → 自动收敛，无需重启应用
- [ ] 远端 token 过期 → 提示「需要重新登录」，**本地笔记照常可读可写**
- [ ] token 过期期间的修改在重新登录后被同步

## 7. 关闭同步 / 切换服务器

- [ ] 关闭同步 → 提示「已停止同步，此设备中的全部笔记仍完整保留」
- [ ] 关闭同步后本地数据一条不少，未同步的修改也保留
- [ ] 从 Server A 切到 Server B → **本地数据不清空**
- [ ] 切换后 A 的 Profile 被停用但记录仍在
- [ ] 切换后 `deviceId` **保持不变**（设置页诊断信息可查）
- [ ] 同一时刻只有一个服务器处于启用状态

## 8. 崩溃恢复

- [ ] 同步推送过程中强杀应用 → 重启后 Outbox 可继续，无重复数据
- [ ] 附件上传中强杀 → 重启后继续上传，不产生半个文件
- [ ] 对账中强杀 → 重启后从当前阶段继续
- [ ] 反复强杀 5 次 → 数据库完好，无半写记录

## 9. Legacy Lite 升级迁移

> **高风险项，务必用备份数据测试**

- [ ] v1.4.x Lite 用户升级到 v1.5.0 → **不得**出现空知识库
- [ ] 迁移前仍能用旧方式访问服务器
- [ ] 触发迁移 → 显示当前阶段（下载中 / 应用中 / 附件 / 校验中）
- [ ] 迁移完成后本地笔记数量与服务器一致
- [ ] 迁移完成后附件图片能显示
- [ ] 迁移中断网 → 保持 Lite 可用 → 重试后能继续
- [ ] 迁移中强杀应用 → 重启后能续跑
- [ ] token 失效 → 提示重新登录，**不标记为完成**
- [ ] 完整性校验失败 → **不切换到本地模式**，仍能用 Lite
- [ ] 迁移完成后重启 → 进入 Local-first，后台同步正常
- [ ] 1000+ 笔记的大库迁移不 OOM、不卡死

## 10. Browser Clipper

- [ ] Desktop 运行中 → 扩展能发现并保存剪藏
- [ ] **没有配置任何服务器**时也能剪藏到 Desktop
- [ ] Desktop 未运行 → 扩展能唤起 Desktop 后保存
- [ ] Desktop 无法唤起 → 剪藏暂存到扩展，Desktop 启动后自动补传
- [ ] 带图文章剪藏 → 图片被本地化为附件
- [ ] 超长文章（10 万字以上）剪藏成功
- [ ] 重复剪藏同一页面不产生异常
- [ ] 浏览器重启后扩展仍能工作
- [ ] 扩展重新加载后暂存队列不丢
- [ ] Chrome / Edge 均验证（Firefox 视 Native Messaging 支持情况）
- [ ] Clipper 无法访问管理员 API（尝试调用应被拒绝）

## 11. 备份 / 恢复

- [ ] 正常备份 → 恢复 → 数据完整
- [ ] 备份 → 在另一设备继续产生新数据 → 恢复旧备份
- [ ] 恢复后同步状态变为「需要重新对账」
- [ ] 下次同步走完整对账，**服务端的新数据不被旧备份覆盖**
- [ ] 恢复后未同步的 Outbox 与冲突记录仍保留

## 12. 性能

- [ ] 1000 篇笔记的库启动时间可接受
- [ ] 连续快速输入 100 次不产生 100 条待同步记录（合并生效）
- [ ] 编辑器输入无明显卡顿
- [ ] 大量附件同步时笔记正文同步不被饿死
- [ ] 后台同步不导致 CPU 持续高占用

## 13. 安全

- [ ] 日志中**不出现** token / 密码 / 笔记正文 / 附件二进制
- [ ] `sync-credentials.json` 权限为 0600（Unix）
- [ ] Clipper 本地接口只监听 127.0.0.1（外部设备访问应失败）
- [ ] 附件下载响应**不包含**服务器文件系统路径
- [ ] 尝试同步他人的 attachmentId → 返回 404

## 14. Docker / NAS 部署

- [ ] 现有 Docker 部署升级后迁移链正常执行到 v90
- [ ] Web 端功能不受影响（Web 仍是 Server-first）
- [ ] 设置 `NOWEN_LOCAL_FIRST_SYNC_V2=0` → V2 端点返回 404，V1 正常
- [ ] 不设置该变量 → V2 正常可用

## 明确未实现（不在本次范围）

以下项**没有实现**，请勿按存在功能验收：

- **Mobile Native Local-first（阶段 I）** —— Android / iOS 仍是 Server-first +
  IndexedDB 缓存。`frontend/src/lib/localRepository.ts` 只是抽象层，
  未接 Native SQLite。
- **Workspace / Team Local-first（阶段 K）** —— 工作区数据不参与 Sync V2。
  服务端会显式拒绝带 `workspaceId` 的同步请求。ACL、成员变更、
  离线权限撤销均未实现。
- **Legacy 代码删除（阶段 P 的删除部分）** —— Full / Lite / switchToFull /
  switchToLite / Offline Queue V1 / Offline Sync V1 全部保留。
  清理清单见 `backend/src/sync/legacyCleanup.ts`。
- **前端 Lite 迁移向导 UI** —— IPC 与后端已就绪
  （`window.nowenDesktop.startLiteMigration()`），但没有可视化引导页面。
- **Conflict Center 的手动合并编辑器** —— 支持保留本机 / 保留服务器，
  「手动合并」需要调用方提供合并后内容，无内置三方合并 UI。

## 诊断入口

排查问题时先看这些：

```
GET  /api/sync/local/diagnostics    # deviceId / 游标 / 待同步数 / 冲突数 / 最近错误
GET  /api/sync/local/engine         # 引擎状态与阶段
GET  /api/sync/local/bootstrap      # 对账进度
GET  /api/sync/local/lite-migration # Lite 迁移进度
GET  /api/sync/local/conflicts      # 冲突列表
```

日志前缀 `[sync-v2]`，字段为白名单（不含正文与凭据）。
