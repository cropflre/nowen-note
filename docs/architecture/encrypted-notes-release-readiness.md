# 加密笔记升级与发布检查

## 适用范围

这份检查覆盖 v1.5.0 SQLite 数据升级到候选版本的兼容性，以及现有加密笔记的测试和构建。
它不代表完整加密交付计划已经完成，也不能替代 Android 真机或 PostgreSQL 验证。
升级不会自动把已有普通 Markdown、富文本和附件转换成密文。

## 自动回归

`backend/tests/encrypted-notes-upgrade.test.ts` 使用 v1.5.0 发布提交
`19a801cba6bf5b4fc7752df09d553c2a8f3c7900` 的真实源码创建旧库，不伪造迁移版本号。
测试仅操作临时目录，并且用独立进程隔离新旧版本的数据库连接。

验证链路：

1. 旧版本创建普通 Markdown、富文本、v1 密文、历史、图片文件和待同步队列，生成完整 ZIP 备份。
2. 复制旧安装目录，在副本上启动候选版本，比较正文、预览、历史、附件记录与图片字节、队列载荷。
3. 使用候选版本的 HTTP 保存接口和同步写入层保存三种笔记，确认版本递增；确认密文降级及明文历史写入被拒绝。
4. 再次启动候选版本，确认迁移幂等和保存结果持久化。
5. 用旧程序打开已升级的副本，确认它拒绝写入新版数据库。
6. 分别在候选版本和旧版本的空安装中恢复升级前完整备份，确认内容和附件恢复。
7. 再次读取升级前源安装，确认测试没有改动原始数据。

需要 Git 历史包含上述发布提交、系统提供 `git` 和 `tar`，以及与运行时 ABI 匹配的后端依赖。
现有 Encrypted Notes CI 已拉取完整历史，并执行这项回归及测试源码的类型检查。

```sh
cd backend
node --import tsx --import ./tests/setup-db-isolation.ts --test tests/encrypted-notes-upgrade.test.ts
cd ../frontend
npm run test:encrypted-notes
npm run build
```

Windows 开发目录若使用 Electron 编译的 better-sqlite3，后端命令应通过
`ELECTRON_RUN_AS_NODE=1` 的 Electron 运行。不要为测试重编译共享的原生依赖。

## 固定候选版本

发布构建必须来自已提交、工作区干净的固定 SHA。并行开发目录的未提交改动不应进入候选构建。
保留候选 SHA、基础发布版本、测试结果和构建日志；若源码变更，应重新验证候选。

组件测试和浏览器验收页初始化实际应用国际化资源并固定为中文，普通测试命令无需额外 setup 配置。
浏览器测试通过翻译后的可访问按钮名称查找预览控件，不依赖未初始化时显示的翻译键。
本次自动回归使用合成数据；真实线上数据和其他平台仍需各自验证。

## 上线与回退

上线前使用旧版本生成完整备份，保留数据库、附件和恢复所需配置，并在隔离安装中确认恢复。
部署可能触发数据库迁移和服务重启，应安排维护窗口并检查启动、保存、同步及图片读取。

如果需要回退，应停止新版服务，在隔离位置使用旧版本恢复升级前备份，再切换回服务。
直接换回旧二进制并继续使用已升级的数据库会被版本保护拒绝。
升级后的新增编辑不会存在于升级前备份中，应先保存当前完整备份再处理回退。

发布前仍需确认：

- 固定候选 SHA 的远端 CI 通过，包括 PostgreSQL 服务测试。
- 目标发布包安装后的启动、普通与加密笔记保存、同步和图片读取。
- Android 真机验证锁定、解锁、重新锁定、后台切换及重启链路。

上述检查不会自动发布、推送或修改线上数据。
