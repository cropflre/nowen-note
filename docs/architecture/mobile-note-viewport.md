# 移动端笔记可视区域（#758）

## 当前行为

- 评论、选中文字批注和回复共用 `InlineCommentBridge` 抽屉。键盘打开后，输入区及发送按钮留在可视区域内，评论列表独立滚动。
- Markdown 和富文本已有单行移动工具栏，高级格式按需展开；原生键盘打开时折叠导航、标签和元信息。正文标题滚出可视区域后由导航显示标题，保留原有阅读与编辑行为。
- 笔记列表的管理菜单，以及编辑页的更多菜单，在手机和小高度桌面窗口中均限高并支持滚动。内部滚动不会关闭列表管理菜单；外部滚动、外部点击和 Escape 保留关闭行为。
- 桌面管理子菜单通过 portal 显示在滚动容器外，避免被主菜单裁剪。子菜单携带同一 `data-context-menu-id`，其内部点击和滚动仍被视为菜单操作。

## 可视区域来源

`frontend/src/hooks/useVisibleViewport.ts` 仅在浮层打开期间订阅事件：

1. 浏览器的 `visualViewport.resize` / `scroll` 和窗口 `resize`。
2. 原生 `useKeyboardLayout` 写入的 `data-keyboard` 与 `--keyboard-height`。

Android Activity 当前使用 `adjustNothing`，键盘覆盖 WebView，不能仅依靠 `100dvh` 或浏览器视口缩放。有效底边取浏览器可视底边和原生键盘上沿的较小值，避免两种通知同时到达时重复扣除高度。关闭浮层后解除订阅；不修改 `body`、`html` 或编辑器整体高度。

## 回归与验收

组件测试覆盖普通评论/批注的浏览器键盘变化、原生键盘避让与恢复、面板重开、菜单内部/外部滚动、末项选择及桌面子菜单。

发布前仍需真机确认：

- Android App 及手机浏览器：打开评论、批注和回复，切换键盘高度，确认输入区、发送按钮和关闭入口可操作。
- Markdown/富文本：编辑时可使用单行工具栏；预览长文时可正常滚动，标题和标签不反复抢占正文空间。
- 手机横屏和电脑小窗口：管理菜单能滚到最后一项，导出/移动等子菜单可进入；键盘收起和屏幕旋转后布局恢复。
