## 1. 交付目标与范围

用户可以在现有笔记菜单中给 Markdown 或富文本笔记设置密码；支持新建、已有笔记转换、局部加密、正文与附件编辑、离线保存、跨端同步、备份恢复、修改密码和明确取消加密。锁定后不能从产品中的列表、搜索、预览、编辑器、历史或附件绕过解锁。

目标平台：现有 Web、Windows/macOS/Linux 桌面 Lite/Full、Android Local-first。本任务不新增 iOS 产品平台；未来 iOS 沿用协议，但必须单独完成真机验收。

“完整”指上述个人笔记生命周期完整。以下为明确边界，不应通过扩大承诺增加未经设计的功能：

- 标题、目录、标签、时间等笔记元数据保持可见；附件原文件名/MIME/描述放入密文。服务器仍可观察密文大小、对象数量、账号和访问时间。
- 加密笔记不支持公开分享、团队共同解锁、明文 Yjs 协作、服务端正文搜索、服务端 AI 或插件自动解密。共享笔记转换前先由用户撤销共享或复制为个人笔记，不自动改变权限或删除他人的内容。
- 原来已保存的明文历史、用户导出、历史备份、离线设备及外部服务副本无法保证全部撤回。旧副本边界必须单独展示，不能宣称取证级物理擦除。
- 忘记密码无法通过重置账号恢复；不新增服务端密钥托管或“忘记密码解密”。不把目录密码/ACL 当作正文加密。
- 保护数据库、应用控制的密文缓存、同步与新备份中的正文和附件；不承诺保护已被控制的客户端、恶意前端更新、截图、主动复制/导出、系统内存取证。

## 3. 协议和密钥决策

### 3.1 保留 v1，新增有版本的能力

- v1 保持原格式、AAD、KDF 和解锁兼容；不更改既有数据的算法解释，不自动批量重加密。
- 新增 `encrypted-note-v2` 和 `nowen-encrypted-v2` 承载明确的文档 schema 版本和附件清单。v1 继续允许编辑其原支持范围；新增 v2 专项验证和独立测试向量。
- 创建或升级为 v2 前确认服务端能力；不支持的客户端只显示锁定占位/升级提示，拒绝修改正文和受保护附件。删除仍遵守原 ACL；删除不能恢复明文。
- 定义 `documentSchemaVersion`、稳定的逻辑对象身份、`keyEpoch`（密钥代次）、`encryptionEpoch`（状态迁移代次）与现有 revision 的作用。schema/key/迁移代次不能互相代替。
- 正文 envelope、局部 envelope、附件包装与附件分块使用不同的固定 AAD 用途。密码学对象身份与数据库 noteId 的映射在可信创建/迁移记录中建立；跨笔记粘贴不能凭传入密文自证身份。
- 离线数据库被完整替换或回滚为合法旧状态的检测不在本次承诺内；同步 revision/epoch 守卫用于应用内并发、旧写入和迁移安全。

### 3.2 解锁会话

- Argon2id 在解锁/创建/改密码时运行；沿用现有候选 64 MiB、3 iterations、4 lanes，先测真机再冻结。不能超时后静默降低参数；参数调整需新版本及兼容测试。
- 新建内部 `EncryptedContentSession`，由专用 Worker 持有非导出 CryptoKey；UI 仅持会话句柄，不把密码/密钥放到 AppContext、日志、持久层或 IPC。
- 同一解锁会话的自动保存只执行正文加密，不每次重新派生口令密钥。每篇/每区会话独立，队列有界；账号、服务器、workspace、对象、keyEpoch 变化立即失效。
- 每次写入用新的 IV；服务端只验证格式、身份、大小、revision/epoch，不能验证 GCM 内容真实性，客户端必须解密核验。
- 关闭、锁定或切号销毁 Worker、编辑器、撤销栈、预览、Blob URL 和会话。JS 无法保证所有字符串的物理清零，文案只承诺应用可达状态释放。

### 3.3 密码与恢复语义

- 新密码至少 12 字符，允许长口令/粘贴，不强制符号组合；提示短密码的离线猜测风险。保留旧 v1 短密码解锁兼容；UI 节流不被宣传为离线攻击防护。
- 改密码需要原密码重新验证，且最新正文、附件、队列、冲突已处理。只重包装当前根密钥；不暗示撤销旧副本或已泄露密钥。
- 旧历史/备份保留其原包装时，需对应旧密码，UI 标明这一点。当前附件密钥由当前根密钥包装，改密码无需重传附件。
- 本次不默认建立恢复密钥或跨笔记统一主密码，避免新增密钥管理模型。密码修改与完整根密钥轮换是不同功能；轮换不混入本次正常改密码。

## 4. 编辑、保存与锁定

### 4.1 文档编辑

- MD 支持当前文本语法、源码/预览、表格、任务列表、代码、公式；RT 支持当前产品已提供的段落、格式、表格、任务、代码、引用、折叠等节点，按实际节点清单逐项验收。
- 复用安全的编辑扩展和 renderer；加密编辑器不能挂载普通上传、Yjs、服务端 AI、正文诊断快照、普通草稿和普通自动保存插件。
- 版本化 schema 校验节点、marks、attrs、URL 协议、深度、大小；不执行任意 HTML/脚本或自动加载远端嵌入。未知节点原样保留于密文并只读提示，不能在保存时静默丢失。
- 内部链接可以保存，解锁后遵守目标 ACL；外部链接正常点击，外部图片必须先导入为受保护附件。远端嵌入只保留链接/占位，不承诺远端内容加密。
- 复制笔记生成独立逻辑对象和根密钥并重加密，附件复制使用独立受保护对象；密文备份恢复为同一对象时保留身份。局部密文复制到另一笔记时重新绑定并重新加密，不能借“复制”绕过身份校验。
- MD/RT 不支持的互转保持现有损失提示；加密区域与附件清单必须无损，不能把加密文本自动解密后写入普通正文。

### 4.2 持久化

- 输入后约 800ms 合并一次密文保存；串行使用最新已确认 revision。内存正文和密文持久层分离；服务端错误不能被伪装成离线成功。
- 离线写入必须通过实际目标存储事务和读回校验：Web 队列/IDB、Android Native SQLite + outbox、桌面现有持久化路径分别验证，不统一退回 Web 队列。
- 保存状态区分“正在保存 / 已保存在本机，等待同步 / 已同步 / 保存失败 / 同步冲突”。“已保存”必须有密文持久化证据。
- 整篇和局部编辑统一自动保存体验：局部编辑只提交密文给主文档，父文档持久化确认后才显示成功。原区域/权限/revision 改变时保留密文草稿并显示冲突，不覆盖新正文。
- 崩溃恢复仅恢复已持久化的密文草稿；OS 强杀前未完成加密的最后输入不能保证恢复，不能用明文临时文件兜底。

### 4.3 后台失败也不能自动露出正文

产品状态至少区分 `locked / unlocking / unlocked / shielding / recovery-required`，保存状态单独管理。

1. 闲置、失焦、隐藏、最小化、休眠、Android 后台、退出/切号触发同步遮挡并卸载可见正文、预览和附件；不等待 HTTP 请求再遮挡。
2. 冻结当前草稿并尝试加密、持久化；网络失败继续本机密文保存。后台异步任务不保证执行完，切到后台前已有检查点可恢复。
3. 完成后释放正文/密钥并显示锁定。保存失败保留密文草稿，重新验证密码后可重试。
4. 如果连加密也失败，仅保留被遮挡的内存修改，进入 `recovery-required`，明确“有未保存修改，锁定尚未完成”；回来重新验证密码才能展示恢复编辑。禁止恢复可见编辑器或伪报已锁定。
5. 切号必须先完成密文检查点或由用户明确放弃；不能把原账号正文留给新账号。关闭/退出在平台允许的范围内阻止脏会话丢失，但不承诺强杀可阻止。

Android 使用实际 App 生命周期事件与原生窗口截图保护；桌面复用主进程/preload 通知。截图保护只覆盖支持的原生窗口，不能宣称 Web 无法截图。撤销历史不包含已锁定明文。

## 5. 附件完整加密

### 5.1 数据模型

- 每个附件生成随机独立文件密钥，由所在整篇/局部根密钥包装。密文正文内的 manifest 存原文件名、MIME、大小、包装密钥、分块信息和完整性记录；外层仅存 opaque ID、所属对象、协议版本、密文尺寸及同步必需信息。
- 原图、缩略图、PDF/音视频/二进制都按受保护附件处理。服务器不生成明文缩略图、OCR、文本提取、转码、向量或预览；显示所需派生物在客户端内存生成，若缓存必须独立加密。
- 加密附件不走普通明文图片 URL、Native 原图解析/相册准备、系统缩略图缓存或明文临时文件。锁定撤销全部 Blob URL/对象引用。
- 所有新上传必须先在客户端加密；服务端仅收密文。附件 access control 继续验证所属笔记和 ACL，加密不能替代授权。

### 5.2 大文件与原子可见性

- 采用有版本的分块格式，初始块大小 1 MiB，每次新内容上传使用新文件密钥。每块 AES-GCM 的 nonce 使用文件级随机 8 字节前缀 + 4 字节块序号，限定块数并拒绝重复/溢出；重试复用原密文，不能同 nonce 加密不同内容。
- AAD 绑定格式、所属逻辑对象、附件对象、上传版本及块序号。受认证 manifest 记录有序块集合、总大小/块数，拒绝调包、乱序、截断与错误结尾；不把传输 SHA-256 当作认证替代。
- 完整格式冻结前建立独立向量、跨端解密和篡改用例。设置现有上传政策对应的单文件/总大小上限，移动端额外测内存峰值。
- 密文附件先暂存上传，读回/完整性核验后，正文 revision 与完整 manifest 在提交事务中切换为可见。失败不产生已保存的破图笔记，暂存孤儿按引用与保留期清理。
- 下载/缓存走现有附件同步通道，但只落密文字节；正文已下载但附件待下载要有可恢复状态。用户主动“保存到设备 / 用其他应用打开”视为明文导出，明确提示并使用受限临时生命周期，不能把导出目录当加密缓存。

### 5.3 既有附件转换

- 原附件保持不动，建立独立密文副本并验证；共享附件不就地覆盖。受保护笔记只能引用新密文对象。
- 最终清理原对象前检查所有笔记、任务、日记、分享和历史引用；仍被普通内容引用的文件保留并报告，不能误删。
- 内联 data URI 先拆为本机受保护附件；远端图片需要用户确认导入，禁止把账号 cookie 发送到任意 URL。下载失败时转换不成功，不能删除原图片占位。
- 清理已无引用的应用控制明文原图、派生缩略图、对象存储副本和本机缓存；旧备份、第三方版本化对象等作为不可自动撤回副本明确列出。

## 6. 已有笔记转换与同步迁移

### 6.1 UI 与前检查

笔记菜单 → 设置加密 → 输入确认密码 → 一段保护范围/旧副本提示 → 转换。无需用户执行数据库命令。保留 noteId、目录、标签和导航上下文。

前检查覆盖实际编辑格式、owner/个人权限、共享、附件引用、历史、块存储、Yjs 房间、向量任务、导入来源、待写入/冲突、缓存、打开的其他窗口以及每个同步 Profile 的来源。

待保存/冲突先处理；附件和普通引用给出可执行处理选项。客户端来源必须来自不走离线回退的已认证读取，携带 version + sourceDigest，并在本机加密后独立解密核对正文、格式与所有附件字节。

默认保留历史：客户端分页读取可管理的原历史，以新根密钥逐条加密并暂存；AAD 绑定 note 逻辑对象、historyId、原版本和原格式，来源版本集合与摘要在提交事务中核对。事务删除旧明文历史后写入已验证的密文历史，不能把删除历史当成默认优化。历史无法迁移时阻止转换，或由用户明确选择“删除旧历史后加密”；已有内部 `discardHistory: true` 原语只能用于这个明确选择，不得在 UI 接入时自动传入。历史数量过大使用有界分批准备，最后原子切换，失败保留原历史。

### 6.2 转换流程

`检查 → 建立写入屏障 → 准备并验证密文/附件 → 提交 → 本机清理 → 同步清理 → 完成`

- 在线同步笔记由其已确定的权威服务端提交转换；纯本机笔记在本机事务转换，首次接入同步直接上传密文。无权威映射/多写入服务端不能猜测来源。
- 持久化 migrationId、sourceRevision、sourceDigest、sourceEpoch、targetEpoch、状态与暂存对象引用；不要在进度表复制正文、密码或明文附件。
- prepare 建立短时有续期、范围限定的写入屏障；覆盖 HTTP、Sync、Yjs、后台派生与附件路径。持锁的异步任务退出后才能提交，跨窗口清理复用现有 Web Locks/转换屏障。
- 服务端事务校验来源及 CAS，写密文、清空 contentText、更新 epoch，清理明文历史/块/FTS/向量/协作快照/导入副本/待同步与冲突引用，登记唯一转换事件。迁移仅用一次性匹配许可，普通 PUT 不获得转换权。
- 附件文件与数据库没有跨资源事务：先写暂存密文，数据库事务切换引用，再按持久化任务清理孤儿/旧对象；重启必须可判断提交是否发生，不能靠最后一个 HTTP 响应推断。
- 服务端只检查来源摘要、密文结构和暂存集合完整，密文能否对应原历史/正文必须由客户端加解密读回核验，不能宣传服务端完成密码学核验。
- 提交前失败保留原笔记并撤销准备屏障；提交后清理失败不得回写原明文，状态为“已加密，清理待完成”，阻止开启旧编辑路径并允许幂等续跑。
- UI 不因超时再次创建另一篇笔记；查询同 migrationId 的提交状态，再决定重试/恢复。允许服务器在客户端离开后继续安全清理，服务端不需要密钥。

### 6.3 跨设备与多服务器

- 转换事件包括稳定对象身份、目标格式/epoch、权威 revision、密文和清理指令。不推送原正文、sourceDigest 所对应的正文或口令。
- 所有修改入口验证 encryptionEpoch + 客户端能力；转换后的旧普通客户端写入一律拒绝。格式未知不能修复为普通笔记，元数据更新也不能回填旧正文。
- 升级设备重新接入时先应用 epoch/转换事件、使旧 activeNote/预览/标签页/分屏失效，再处理旧 outbox。不可把旧明文放入常规冲突历史；旧待编辑副本需要用户解锁后加密成恢复副本，或明确放弃，不能静默删除。
- 新密文落盘与本机旧正文/派生缓存失效在可用事务内共同提交；再清理附件文件/缓存并读回。暂存/清理失败有独立恢复状态，不能使用 Native 投影回退露出旧正文。
- 多个服务端同步 Profile 涉及多数据库，不能宣称全局原子事务。先协商全部参与服务端的能力与 prepare 屏障，使用持久协调记录推进；某端提交后只能恢复并继续提交/清理，不能把已经转换的服务端回滚为明文。未完成时保持迁移待完成及写入屏障。
- 旧服务端不支持协调时先升级，否则转换阻止并说明。离线客户端副本不要求一直在线才能完成权威端转换，但列为待清理；重新联网才能确认，完全离线时无法远程撤销其旧明文。
- 全新 bootstrap、增量同步、补快照、备份恢复均携带 epoch；缺失旧事件时通过当前状态重建清理，不能要求保留所有旧 outbox 正文才能工作。

### 6.4 数据残留边界

- 必须测试应用 API、数据库普通表/虚拟表、FTS shadow tables、历史、同步事件/冲突、Yjs、embedding、缓存/队列、附件派生物、新备份均无受保护明文。
- SQLite 针对受影响存储做受控索引重建、checkpoint/整理并扫描当前 DB/WAL；不能因执行 `secure_delete` 或 `VACUUM` 就声称物理擦除。PostgreSQL 的 WAL/MVCC/备份同样属于单独的存储运维边界。
- 当前应用管理副本的清理证据与历史备份/文件系统快照/离线设备的不可撤回边界分开报告；普通 UI 不使用“所有历史痕迹已删除”。

## 7. 取消加密、历史、备份与导出

- 取消加密需要重新验证密码，等待正文/附件同步且无冲突，提示将生成明文；走反向 migrationId + CAS + epoch 流程，先在客户端准备普通正文/附件并校验，再提交，不能用普通 PUT 降级。
- 取消后当前笔记及后续保存为普通格式，原密文历史仍按对应密码访问；不自动解密所有历史或外部备份。清理不再引用的受保护附件时保留仍被密文历史引用的对象。
- 历史在客户端解锁查看，切版本不写回明文；损坏历史保留原数据，明确对应密码/keyEpoch，不提供后台解密。
- 转换产生的历史默认同当前根密钥解锁；已存在的独立 v1 envelope/后续旧包装历史仍保留其密码语义。改密码不等于重新包装全部历史，必要时明确要求对应旧密码，不允许后台猜测或静默丢弃历史。
- 密文备份默认包含正文、全部被引用的密文附件、历史、epoch 与必要元数据；恢复到干净设备只依赖备份和对应密码。备份一致性检查不能跳过暂存/缺失附件。
- 普通 Markdown/HTML/PDF/DOCX 导出默认跳过锁定内容或输出明确占位，不能输出伪成功的空正文；用户显式解锁并选择明文导出时提示目标文件不再受密码保护。
- 用户可导出密码保护的独立密文包；恢复保留对象身份，导入为新副本则解锁后新建身份/根密钥。导入未知加密版本禁止降级。
- 加密内容不发送给 AI/插件。局部普通正文的搜索/AI 只提取公开文本，密文标记不当作语义文本；解锁正文不进入全局搜索索引。

## 8. 实施顺序与提交边界

同一交付目标拆成可审查提交，每项先建立失败回归再实现；全部门禁通过才开放正式能力。

| 顺序 | 交付包 | 必需验证 |
| --- | --- | --- |
| 1 | 盘点文档 schema/存储来源/客户端能力；冻结 v2、附件格式、AAD、epoch 与错误码 | v1 向量仍兼容；独立 v2 向量；篡改/越界/未知版本拒绝 |
| 2 | 会话 Worker、合并保存、立即遮挡、失败恢复、整篇/局部自动保存 | 保存/锁定/切号/权限变化竞态；无主线程口令持久化；无错误成功状态 |
| 3 | 完整 MD/RT 文本格式与 renderer、复制/互转/撤销隔离 | 每个现有节点/属性 round-trip；未知节点不丢失；无外部脚本/上传/Yjs |
| 4 | 客户端附件加密、分块、manifest、服务器 opaque 存储与缓存 | 字节一致；调包/乱序/截断；内存有界；缩略图/日志/缓存无明文 |
| 5 | Native SQLite/outbox/附件适配与 Android 生命周期接入 | 实机 Worker/KDF；离线强杀恢复已确认密文；后台遮挡；账号隔离 |
| 6 | 服务端迁移协调与前/后向事务、跨端 epoch/旧写入守卫 | 多连接/跨进程/多端并发；超时已提交；部分提交续跑；旧设备重入 |
| 7 | 产品转换、取消、历史、备份导出闭环与当前副本清理 | 含附件已有笔记转换；清理失败续跑；新设备恢复；旧明文队列隔离 |
| 8 | 部署兼容、安装升级、双设备与真机安全/性能验收 | 发布包和真实服务；版本升级/不支持降级；最终明文扫描与文档 |

协议设计阶段必须完成独立密码学设计复核，重点为附件 nonce、manifest 认证、身份绑定、跨设备 epoch 与复制语义；应用测试通过不能替代协议审查。

复用现有同步/存储/导出通道，新增内部 `EncryptedContentSession` 和 `EncryptedAttachmentCodec` 即可；不创建第二套同步系统、加密中心、插件 SDK 或与任务无关的全局编辑器重构。

## 9. 测试矩阵与完成门禁

### 9.1 自动化

- 核心：旧/新向量、Unicode、随机性、错误密码、认证失败、AAD/身份替换、包装/正文 nonce、参数/大小边界、Worker 超时/取消/销毁。
- 编辑：MD/RT 所有实际支持节点；选择/插入/保存/锁定/重开；重复区域；只读/权限变化；复制/撤销/MD–RT 互转；连续输入并发保存；失败时不露出编辑器。
- Native/浏览器存储：账号/服务器/workspace 隔离；IDB/队列/SQLite 配额或写入失败；实际读回；旧缓存回填；强杀/重启；明文/口令/密钥不进入存储。
- 迁移：每阶段注入失败；来源改变；prepare 过期；清理在途请求；双窗口；部分服务端提交；跨进程重启；旧客户端 PUT/Sync/Yjs/附件写入拒绝。
- 同步：离线编辑/重连、改密码冲突、迁移与旧编辑冲突、bootstrap/增量/补快照、异常 ACK 不丢本机密文；跨服务器与新设备恢复。
- 附件：图片/PDF/音视频/二进制；共享引用；0 字节/大文件/重复下载；上传中断/重试；manifest 不一致/块调包/截断；旧原图/缩略图/外链/内联转换。
- 备份：独立进程干净数据库恢复；附件/历史完整；缺件和损坏不宣称成功；旧/新版本混合；密文包与明确明文导出。
- SQLite/PostgreSQL：真实引擎守卫/迁移测试。没有测试连接必须记录跳过，不把跳过计为覆盖；不触碰产品数据库或重建共享 native 依赖。

扫描使用公开专用标记，覆盖网络载荷、AppContext、普通草稿、local/sessionStorage、IDB、Native DB、DB/WAL、附件目录、对象存储、日志/诊断、新 ZIP。外层元数据允许的信息单独列出；不是扫描一次测试字符串就证明所有明文不可泄露。

### 9.2 实际产品与安装包

| 平台/部署 | 必须实际走通 |
| --- | --- |
| Web HTTPS，含反向代理和非根路径 | 创建/转换/附件/离线/冲突/锁定/恢复；真实 CSP + Worker/WASM |
| Windows/macOS/Linux Lite 与 Full | 安装/升级、实际资源及后端、账号切换、失焦/隐藏/最小化/休眠/重启 |

| 两台真实设备连接真实服务端 | 一端转换另一端在线/离线；改密码；旧队列重入；附件/历史/新设备恢复 |

建议性能验收目标（需要实测，不是当前成绩）：主流 Android 解锁 p95 ≤ 2s、桌面 p95 ≤ 1s；每次 KDF 内存记录实际峰值，不把 64 MiB 参数当进程总内存；1 MiB 分块附件读写内存有界；连续编辑不在主线程运行 KDF；后台事件下一次可绘制帧已遮挡正文。达不到先优化会话/调度，不静默降级加密参数。

- [ ] 单服务端/多服务端同步、旧写入、离线设备重入、冲突及异常 ACK 通过。
- [ ] 当前可管理明文副本完成清理或明确处于未完成状态；新备份恢复通过，旧外部副本限制准确。

- [ ] 文档/UI/能力版本/CI 与实际范围一致，不以测试数量或主观百分比代替完成条件。

## 11. 规范依据

- [现有 Epic](./encrypted-notes-epic.md)、[v1 格式](./encrypted-notes-envelope-v1.md)、[M2](./encrypted-notes-m2.md)、[M3](./encrypted-notes-m3.md)、[M4](./encrypted-notes-m4.md)。
- [RFC 9106 §4 / §7.4](https://www.rfc-editor.org/rfc/rfc9106)：Argon2id 参数与按硬件选择参数的依据；不能替代本产品移动端测试。
- [W3C Web Cryptography AES-GCM](https://www.w3.org/TR/webcrypto/#aes-gcm)：IV、AAD、认证标签与 Web Crypto 行为；本方案分块格式仍需独立设计复核。
- [SQLite secure_delete](https://www.sqlite.org/pragma.html#pragma_secure_delete)：虚拟表 shadow tables，特别是 FTS，可能仍保留删除数据痕迹；不能以开启 pragma 宣称完全擦除。
