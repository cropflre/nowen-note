## 文档与编辑边界

Markdown 使用 `nowen-encrypted-v1` 围栏，围栏内只保存完整 JSON envelope。富文本复用带相同语言标记的 `codeBlock`，NodeView 展示不可直接编辑的锁定卡片，没有另建文档 schema。这个视图不是新 schema 的 atom 节点；旧客户端可能显示密文代码块，也可能在本地删除或改坏区域。notes API/Sync V2 的内容写入需要 `encryptedBlocksVersion: 1` 能力声明：新增、保留、修改或删除区域均检查；没有声明的旧写入器会被拒绝，即使正文未变。此声明只在请求、Snapshot 和冲突载荷中传递，不新增数据库字段，也不是认证凭据。现代客户端可以明确删除区域，API 还要求当前正整数 `version`，Sync 延用 `baseVersion`。元数据更新不涉及正文时不要求声明。SQLite/PostgreSQL v118 触发器对含保留标记的正文或格式更新要求精确匹配目标笔记、正文和格式的写入许可；应用写入器在事务中创建并清理许可，PostgreSQL 还绑定当前事务 ID。块 Patch 只能修改公开正文，必须保留完整 envelope 多重集合；含区域的笔记停用 Yjs。SQLite 旧版启动另有 schema 降级拒绝。这些措施保护应用写入路径，不能阻止能自行删除触发器的数据库持有者，也不保证旧客户端本地编辑器保留密文。

公开正文仍按普通笔记保存、搜索、分享和导出。含局部区域的笔记会停用实时 Yjs 协作和 Yjs 子文档，避免旧协作状态广播后改坏区域；区域编辑在独立弹窗完成。加密区域的口令与解锁正文不会插入主 CodeMirror/ProseMirror/Yjs 文档。弹窗的“加密写回”完成后，主文档仍需通过笔记原有保存流程持久化，不代表服务器已确认。保存失败时主文档保留密文，未写回的草稿仅在弹窗内存中。

首次只允许在普通空白行/段落光标处新增内容，不提供将已有普通明文选区转换成密文。已有明文历史、缓存、WAL、旧备份清理属于 M4。区域内新内容为 Markdown 文本，含图片、附件或嵌入的内容会拒绝；导入的受支持基础富文本 envelope 可以临时编辑。区域口令至少 12 字符，创建时二次确认并说明无法恢复。

打开区域时固定原密文和写入守卫。写回时检查文档/区域、权限及笔记身份；原区域被修改时拒绝覆盖并保留弹窗草稿。CodeMirror 写入是独立撤销事务。格式转换前后比较完整 envelope 多重集合，包含重复区域；转换丢失、改变或误修复围栏会抛错。修复了已有围栏恢复逻辑将带语言围栏误算为不平衡的情况。Markdown 源码修改仍可破坏密文，必须保留原始副本。

复制按钮只复制版本化密文围栏，不复制解锁正文。用户在临时正文编辑器主动复制明文属于用户操作，无法阻止截图或被控制的客户端。关闭弹窗销毁临时编辑器；未写回修改会确认放弃，切换普通笔记/视图时会阻止导航，切换账号/服务器会中止 Worker 并锁定。没有闲置/后台自动锁定，也不承诺 JS 物理内存擦除。

服务端对创建、更新和已有共享 Sync 写入边界进行结构校验，拒绝未知保留语言、错误 kind、缺失字段、超出参数上限或不完整围栏；SQLite/PostgreSQL 触发器拒绝未授权的局部密文改写，块 Patch 要求保留完整区域集合。服务端没有口令，不能认证 GCM。块索引和 `contentText` 跳过区域密文，周围公开正文仍可索引。普通笔记的历史/块快照允许保存公开正文与 envelope；不存在解锁正文传输到服务端的步骤。

局部区域冲突与整篇密文一样不允许三方智能合并或 JSON 手动合并，也不自动解决普通离线队列中的冲突；即使只有服务器版本包含区域，也保持待处理。明确保留本机时读取完整队列载荷，不读取普通草稿缓存。历史本机载荷没有能力字段时仅在用户明确选择后补声明；远端载荷在冲突落库和应用前检查，失败不推进游标或丢弃原密文。部分 Sync upsert 缺少正文时按实际 SQL 默认值校验，不能利用缺字段绕过保护。
