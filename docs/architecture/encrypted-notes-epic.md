# Encrypted Notes Epic：整篇笔记与局部内容加密

状态：M1 核心已实现，M2 已接入实验性整篇文本编辑与 SQLite/离线密文保存，同步/完整 ZIP 恢复与 PostgreSQL 16 迁移自动化验收已通过，真实产品双设备与安装包验收仍待完成；M3 新增局部加密文本实验入口，完整验收未完成。M0 参数冻结仍待移动端实测。来源：[Issue #749 第 9 项](https://github.com/cropflre/nowen-note/issues/749)。跟踪：[Epic #796](https://github.com/cropflre/nowen-note/issues/796)。协议与验收：[内部 envelope v1](./encrypted-notes-envelope-v1.md)。

## 用户目标与验收边界

用户能为整篇笔记或指定内容设置独立口令。锁定时显示占位，解锁后可阅读、编辑，再锁定后释放当前会话中的明文。复制数据库、同步数据或功能启用后生成的密文备份，不应直接读到受保护正文。

现有 `isLocked`、目录密码和 ACL 保留原含义，不能作为内容加密标记。标题、标签、目录、时间、颜色等元数据首版保持可见，界面必须明确这个边界。附件加密不自动包含在正文加密承诺里；支持附件前，拒绝把含附件、嵌入或外部资源的笔记转换成“整篇加密”，不能静默留下明文附件。

客户端解密后才能展示正文。服务端不持有口令或可解密的正文密钥，不做服务端解密兜底。此设计防护数据库/备份/服务端存储泄露，不承诺防护已被控制的客户端、恶意前端更新、截图、用户主动复制或导出后的明文。

已有的旧备份、曾同步到其他设备的明文和外部副本不能通过一次加密转换追回。转换流程必须说明历史副本的处理范围；不能把“当前正文已加密”宣传为“所有历史痕迹已消失”。

## 当前架构影响

| 能力域 | 现有接入点 | 必须改变的行为 |
| --- | --- | --- |

| Search / AI | `searchIndex.ts`、`embedding-worker.ts` | 加密正文不进入服务端 FTS、全文提取、向量索引或 AI 上下文 |
| Sync | `syncOutboxCaptureMigration.ts`、`sync/bootstrap.ts`、现有 Sync V2 | 复用已有同步通道传密文，快照、冲突副本和旧客户端都保持密文语义 |

不要另起一套同步系统。加密模块先是客户端内部能力；在权限和生命周期稳定之前，不开放插件解密 API。

## 建议的密码与密文格式

以下设计已在内部核心实现，M2 产品实验入口见 [整篇文本接入记录](./encrypted-notes-m2.md)，不冻结 Public API。格式、候选参数与依赖以 [envelope v1](./encrypted-notes-envelope-v1.md) 为准。

- 每篇笔记/每个加密区域生成随机 256 位内容密钥（DEK），每次加密生成新的 96 位 IV，使用 AES-256-GCM 和 128 位认证标签。
- 口令经 Argon2id 派生包装密钥（KEK），使用独立随机盐；KEK 用 AES-GCM 包装 DEK。修改口令时重新派生并包装 DEK，不重新加密全部历史正文。
- 包装密钥和正文加密使用不同 IV 与不同 AAD 用途标记。AAD 固定序列化，绑定 envelope 版本、密文对象 ID、note/block 类型及原始内容格式，防止替换对象或错误解释格式。
- 逻辑密文对象 ID 在复制/导入时保留，用于认证；数据库 note ID 或 workspace ID 不直接作为不可迁移的认证字段。复制并建立独立密钥或跨域迁移时必须显式重新加密。
- 密钥与口令仅保存在解锁会话内，不进入 localStorage、IndexedDB、数据库、日志、错误报告或同步消息。持久化的只能是盐、参数、IV、wrappedKey、ciphertext 和认证标签。
- 错误口令、损坏密文或认证失败均返回可重试的解锁失败，不覆盖原密文。未知版本/算法、异常长度和超出上限的 KDF 参数应拒绝，不能自动当明文解析。

内部 envelope v1 已定义 `version`、`algorithm`、`kind`、`objectId`、`originalFormat`、`kdf`、`wrappedKey` 和 `payload`，使用规范 base64、尾附 GCM 标签和固定 AAD；已建立独立 Node/OpenSSL 测试向量。正式跨端格式仍待 M0 验收冻结。

Argon2id 在 Worker 中运行。依赖版本、WASM 构建、内存/耗时参数和输入上限先在 Web、Electron、Android、iOS 实测后确定，并把参数写入 envelope；不未经测量就硬编码桌面参数。AES-GCM 使用 Web Crypto，Web 部署必须满足安全上下文要求；能力不可用时禁止创建/改写加密内容，不回退到服务端或弱算法。

## 两种文档模型

**整篇笔记：** 服务端正文存储 envelope，解密后的 Markdown/Tiptap 原始格式只存在于客户端会话。`contentText` 不包含正文；服务端普通解析、格式修复、块提取和索引逻辑必须跳过。首个交付阶段支持新建文本笔记；既有笔记转换在历史明文清理方案通过验证后交付。

**局部内容：** 当前实验入口复用带保留语言的 codeBlock 与不可编辑 NodeView，尚未新增 schema atom；Markdown 使用显式的加密围栏与版本化 envelope。解锁内容在临时编辑区修改，加密完成后写回原区域；不把解密内容插入主文档或主 Yjs 文档。普通内容照常可搜索，受保护区域始终只参与密文保存、同步、历史和格式转换。源码模式只能看到 envelope。

整篇加密与局部加密共用经过验证的 envelope/密钥组件，但由不同编辑器入口承载。MD/RT 转换、复制、撤销/重做不能丢失密文区域或生成明文副本。首版不支持多人共同编辑解锁明文，也不允许插件或服务端 AI 自动获得解锁内容。

## 生命周期、保存与恢复

1. 创建：先校验能力、口令确认和支持的内容类型；客户端加密成功后才持久化密文。
2. 解锁：认证成功后建立内存会话，打开受控编辑区；不得把正文或密钥写入普通持久化路径。
3. 编辑：使用现有修订/CAS 与同步队列提交密文，未完成加密的草稿不能排队。失败保留原密文和会话中的待保存内容。
4. 手动锁定/切换笔记：先确认密文保存成功；失败时阻止丢弃并提供重试或明确放弃。自动锁定现支持 Web/桌面 5 分钟闲置及后台事件。整篇笔记停止输入后自动加密保存，锁定等待正在进行的写入，并补存最新编辑；服务器确认或离线密文队列读回成功后才清除会话。失败明确报告锁定未完成并保留编辑，暂停自动重试。局部内容仍使用仅内存密文草稿，重新解锁恢复后显式保存。退出账号清理会话和临时草稿。移动端挂起处理仍待真机验收。
5. 同步冲突：保留双方密文版本，解锁后由客户端处理冲突；服务端不能尝试明文合并。
6. 改口令：原口令验证后，以新盐和新 KEK 包装 DEK，并通过原子修订更新；失败时原 envelope 仍可解锁。旧备份仍可能使用旧口令，新口令不撤销已泄露的旧密钥。
7. 恢复：在干净设备导入密文备份，使用对应口令解锁；不依赖服务端秘密或原设备。首版不提供账号重置解密，口令丢失无法恢复正文，创建时明确告知。

JavaScript 无法保证所有内存副本被物理清零；锁定验收针对应用可达对象、编辑器状态与持久化/传输路径，不宣传绝对内存擦除。

- 使用唯一正文标记创建整篇与局部加密笔记，分别在锁定和解锁编辑后检查 HTTP/WebSocket 载荷、SQLite/PostgreSQL、FTS、历史、块快照、同步快照/队列、IndexedDB/Yjs、向量索引、日志与新备份；受保护标记不能出现。
