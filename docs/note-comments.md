# 评论中心与站内通知（#749 第 7 项）

## 使用入口

- 在「分享管理」中点击「评论管理」，或从通知中心打开评论管理。
- 默认显示未解决评论，可以切换全部/已解决，按笔记标题或评论正文搜索并分页查看。
- 列表展示原笔记、作者或访客昵称、时间、评论正文和状态。管理员可标记解决、重新打开、确认删除，或打开原笔记的对应评论线程。
- 已解决线程中的回复也能通过评论中心或通知定位；笔记正文仍使用原有评论抽屉。

## 通知规则

- 新评论通知笔记所有者；回复还会通知被回复评论的登录作者。
- 接收者重合时只生成一条通知，排除发言者本人、禁用账号及已无笔记读取权限的用户。
- 公开分享中的访客评论会通知所有者，访客本人没有站内通知收件箱。
- 个人笔记和工作区笔记均支持。通知中心沿用未读数量、单条已读、全部已读和 45 秒轮询；回到窗口时刷新。
- 点击通知先标为已读，再按当前权限读取笔记并定位评论。评论或笔记被删除、笔记进入回收站后，相应通知不再显示。

## 权限与数据

- 评论中心复用现有 Knowledge ACL 的管理能力。普通查看者/评论者不能通过聚合接口管理他人笔记。
- 评论读取、管理以及通知展示都检查目录密码，未解锁的受保护笔记不显示正文摘要；有效解锁令牌可恢复访问。
- 权限撤销后通知立即隐藏，不能借历史通知继续访问或标记已读。账号或服务器切换会丢弃旧请求结果。
- 评论与通知在同一事务中保存。通知写入失败时评论创建一并回滚。
- 这是服务端协作能力，纯移动本地离线账号不访问评论中心和站内通知接口；评论操作不写入笔记离线队列。
- SQLite 迁移 116 保留已有议题通知和已读状态，并允许个人空间通知的 `workspaceId` 为空；对应 PostgreSQL 迁移同步放宽该列。
