# 树列表滚动条性能修复设计

## 目标

保留桌面端树列表自绘滚动条的可见、拖拽和键盘操作能力，同时消除滚动条桥接对整页 DOM 的持续监听，避免长笔记编辑或窗口化挂载时触发全页扫描和强制布局。

## 根因

当前桥接在应用启动时监听 `document.body` 的全部子树。任何无关区域的节点增删都会触发滚动条协调流程，扫描整个文档并读取树容器布局。长文档连续挂载节点时，该流程会逐帧占用主线程。

## 方案

1. 删除覆盖 `document.body` 的 `MutationObserver`。
2. 导出一个轻量的协调入口，由桌面 `Sidebar` 挂载和卸载时主动调用。
3. 保留树滚动容器内部的内容观察器，用于更新滚动块尺寸。
4. 只观察滚动容器的直接父节点，轨道被外部代码移除时再触发一次协调，不监听其它页面区域。
5. 保留窗口尺寸变化时的协调逻辑。

## 验收

- 无关区域增删 DOM 不再调用全页树选择器。
- 桌面侧栏挂载后能创建滚动轨道。
- 轨道被移除后能自动恢复。
- 几何、运行时回归测试和前端生产构建通过。
