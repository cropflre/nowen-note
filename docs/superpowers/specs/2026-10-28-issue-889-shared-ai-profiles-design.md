# Issue #889：管理员共享 AI 模型配置开发方案

日期：2026-10-28。状态：已按本方案实现本地代码，未提交、发布；真实服务与各平台真机验收仍待完成。

需求来源：https://github.com/cropflre/nowen-note/issues/889 。分析时 Issue 为 open，无评论。代码基线为本地 `release/v1.5.4`，不代表已经发布的行为。

## 1. 需求理解与建议决策

用户希望管理员配置好 AI 模型后，选择需要共享的成员，让成员直接看到并使用，避免每人重复填写同一服务地址、密钥和模型。诉求覆盖全平台。

建议将功能命名为“共享 AI 配置”。这里共享的是模型服务的使用权限，成员不获得凭据，也不自动获得管理员的笔记、知识库或对话记录。

Issue 尚未明确“AI 管理员”指系统管理员还是工作区管理员。当前代码有系统管理员 `users.role=admin`、工作区角色，没有独立 AI 管理员角色。本方案采用以下一期假设，评审时可调整：

- 系统管理员维护实例级共享配置，选择当前实例中的指定账号作为使用者。
- 普通用户只看见自己被授权的共享配置，保留个人配置；共享配置由系统管理员统一维护。
- 授权后立即可见，成员自行点击“启用”，不自动覆盖其当前选择。
- 同一成员的选择属于账号；缓存另外按服务器实例和账号隔离。
- 获授权账号可以在个人空间及其有权访问的工作区使用该配置。若希望仅能在某工作区使用，则必须改为工作区授权模型，不能只给列表增加过滤。

一期不增加工作区管理员授权、全部用户自动授权、强制默认模型、额度结算、复杂审批或 Embedding 共享。它们不是 Issue 当前明确要求的范围。

## 2. 现有实现与改动原因

| `backend/src/services/embedding-config.ts` | Embedding 可绑定个人 Profile，也可回退到个人聊天连接字段 | 本期不让共享聊天凭据自动进入 Embedding 或后台索引 |

既有设计 `2026-07-15-user-ai-settings-isolation-design.md` 明确按用户隔离 AI 配置。本次应增加显式授权的共享资源，不能恢复“所有用户默认读取全局 ai_*”的旧行为。

## 3. 用户交互

### 管理员

1. 在原 AI 设置中进入“共享配置”，复用个人配置的服务商、地址、密钥、自定义请求头、模型及连接测试表单。
2. 可新建共享配置，也可将自己的个人配置“发布为共享配置”。发布在服务器内部复制一次，形成独立共享资源；后续修改原个人配置不自动修改共享版本。
3. 开启共享并勾选指定成员，保存配置和授权清单。
4. 支持修改配置、增减成员、暂停使用及删除。共享配置更新后，新发起的调用使用最新配置，不需要逐个成员更新。
5. 共享资源由系统管理员统一维护，不随最初发布者退出登录而消失。发布者被删除也不能通过外键级联误删资源。

### 成员

1. 在 AI 设置和聊天模型选择器中看见“个人配置”“共享配置”，共享条目标记“管理员提供”。
2. 共享条目显示名称、服务商、模型和可用状态，不提供地址、密钥、自定义请求头编辑或复制入口。
3. 点击“启用”后可使用现有聊天、编辑器 AI、摘要、知识问答、任务 AI 和 Agent 中适用的聊天能力。模型本身仍需满足现有能力要求，例如 Agent 的工具调用能力。
4. 可以随时切回个人配置。共享授权不会改写或删除个人配置。
5. 当前共享配置被暂停、删除或撤权后，显示“当前共享配置不可用，请重新选择”；保留选择信息供解释，不静默使用其他模型或个人付费凭据。
6. AI 总开关关闭时，个人及共享聊天调用均不得绕过关闭状态；重新开启时重新校验所选共享配置。

空列表、加载失败、授权变动、服务器不可达及旧服务器不支持共享能力均需有明确状态。共享列表在进入设置、打开模型选择器及窗口重新激活时刷新；撤权安全性依赖服务端检查，不依赖界面刷新或实时消息。

## 4. 数据与凭据边界

新增两张服务端表，具体命名随仓库约定统一：

| 表 | 主要字段与约束 |
| --- | --- |
| `shared_ai_profiles` | `id`、名称、provider、apiUrl、apiKey、customHeadersJson、model、enabled、revision、createdBy、createdAt、updatedAt；createdBy 仅为审计信息，删除创建者不级联删除配置 |
| `shared_ai_profile_grants` | `profileId`、`userId`，联合主键；删除配置或成员时清理对应授权 |

在 `user_ai_settings` 增加允许键 `ai_active_shared_profile_id`。为空时使用现有个人选择；非空时由共享解析器处理。原 `ai_active_profile_id` 保留最近的个人选择，二者不代表两套同时生效的聊天配置。

- 启用共享：只记录共享 ID，不复制任何共享连接字段到成员设置、关闭备份字段、浏览器存储或 Native 数据库。
- 启用个人：清空共享 ID，再使用现有个人启用链路。
- 管理员更新配置与授权清单在一个事务内完成；用 revision 拒绝过期编辑覆盖新配置。
- 成员列表 API 返回专门的公开结构，不能直接复用含地址和密钥尾号的个人 Profile 序列化函数。
- 密钥及自定义请求头值只在服务端解析。管理员读取也只得到掩码，修改时遵守既有保留密钥语义；日志和上游错误继续脱敏。
- 使用现有服务端凭据存储边界；本方案不宣称数据库凭据已静态加密，也不为此重构整个密钥系统。

共享模型只改变服务凭据来源。笔记检索、任务、附件和 Agent 工具操作仍使用请求成员身份与现有 ACL，不能切换成发布管理员身份。

## 5. API 与统一解析

以下为建议路径，实施时与现有路由注册及 Token 策略统一：

| API | 用途与权限 |
| --- | --- |
| `GET /api/ai/profiles/available` | 登录用户读取个人及已授权共享配置的公开列表、当前选择和共享能力版本 |
| `PUT /api/ai/profiles/active` | 提交 `{ scope: personal/shared, id }`，服务端校验归属或授权后保存选择 |
| `/api/ai/shared-profiles` 的 GET/POST | 系统管理员列出或创建共享资源 |
| `/api/ai/shared-profiles/:id` 的 PUT/DELETE | 系统管理员更新资源、授权及状态，或删除 |
| `POST /api/ai/shared-profiles/:id/test` | 按保存的服务端配置测试；一期只向管理员开放 |

共享管理接口复用可信认证用户及 `requireAdmin`，不得相信客户端提交的管理员角色。管理路由一期要求登录会话，明确拒绝 PAT；已有 AI 调用接口保持其 Token scope 和资源约束，授权共享模型不扩大 Token 权限。

增加 `resolveUserChatSettings(userId)` 一类统一入口，将“个人原始配置读取”和“实际聊天调用配置”区分开：

1. 检查 AI 总开关。
2. 若有共享 ID，检查资源存在、已启用、账号获授权，随后在服务端解析完整连接配置；无效时返回明确的共享不可用错误，不回退个人。
3. 没有共享 ID 时沿用当前个人配置。
4. 调用原有 AI client、provider 和出站请求链路。

需逐一核对 `/ai`、`ai-reliable`、任务 AI、asset-ai、Agent runtime/workflow 等实际聊天调用者，不能只修改聊天窗口。Agent 后续模型轮次和后台多次调用应重新检查授权，避免长期持有旧授权的配置快照。

撤权承诺是：撤权事务提交后，新开始的调用及下一轮模型调用不得通过授权检查。已经发送到上游的请求可能完成，不能承诺追回已发送内容或绝对中止正在返回的流。

成员不能借共享 ID 进入个人 Profile 的 test-draft/discover-models 接口，再覆盖 apiUrl、provider 或请求头，把共享凭据发往其他服务器。共享连接字段仅能由管理员管理接口修改；成员调用使用保存的共享模型参数。

## 6. 兼容与全平台范围

### 个人接口与 Embedding

- 原个人 Profile CRUD 及 `/ai/settings` 继续管理个人数据；共享生效状态通过独立的公开摘要表达，不把共享密钥合并进旧设置响应。
- 原个人启用接口、旧客户端直接保存聊天连接字段时退出共享选择；只保存 Embedding 或超时字段不退出共享选择。
- `ensureAIProfiles` 对个人默认项的补全不能覆盖共享选择。
- AI 总开关的恢复逻辑不能将共享凭据写进个人备份，也不能绕过重新授权。
- `resolveEmbeddingConfig` 本期只读取原个人配置或独立 Embedding 设置；共享项不进入 Embedding 配置选择器。知识问答的聊天生成可用共享模型，向量检索仍需要独立配置，不能据此声称团队向量索引已开通。

### 平台和运行模式

| 场景 | 开发与验收边界 |
| --- | --- |
| Web、直接连接服务器的桌面/移动客户端 | 从同一服务器读取授权列表和使用共享配置；分别验证认证、流式返回、前后台切换与模型选择 UI |
| 桌面 Full 内嵌后端 + 远程同步 | 当前 API 可能指向本地服务，远程授权不会自动出现在本地库。需单独完成远程共享服务调用设计，不能当作普通前端复用已支持 |
| Native 仅本机或断网模式 | 共享服务需要在线授权；不下载共享密钥。提示连接服务器，保留本地个人配置和未同步数据 |
| 旧服务器或旧客户端 | 用能力探测控制新入口；保留旧个人配置链路。旧客户端不承诺提供共享管理和选择体验 |

对于桌面 Full + 远程同步，建议先做小范围技术验证：用绑定服务器账号访问共享模型目录，并通过受限的模型调用通道使用远端共享服务；本地笔记读取、工具执行和保存仍在原有本地链路，不能简单把整个 Agent/RAG 请求转到服务器。通道仅允许指定共享模型调用，不能成为可指定任意上游地址的通用代理。该场景应作为独立交付项；未完成前只能标明部分运行模式支持，不能关闭 Issue 的“全平台”验收。

共享配置和授权是服务器管理数据，不新增笔记 Sync V2 实体，不进入成员 Outbox。客户端只缓存公开元数据，缓存和异步响应按服务器实例、账号隔离；切换身份时立即失效。

### 迁移、备份与回滚

- 迁移只新增表及设置键，不把历史个人配置自动发布，也不改变现有成员配置。
- 新库 schema 与 SQLite 增量迁移一致；对应 PostgreSQL schema/适配路径保持一致，不以此宣称 PostgreSQL 生产验收完成。
- 完整服务器备份需包含共享配置、授权和选择引用，并验证恢复关系；个人笔记导出、配置复制、普通同步包不得夹带共享凭据。
- 回滚功能时停止解析共享选择并提示成员重新选择个人配置，保留个人数据；数据库降级遵循已有 schema 版本约束，不承诺旧程序能直接打开新库。

## 7. 开发拆分与验收

| 阶段 | 交付 | 验证 |
| --- | --- | --- |
| 1. 服务端授权与模型解析 | 数据表、迁移、管理 API、成员目录与选择、聊天解析器、总开关及 Embedding 边界 | 临时数据库行为测试和真实 HTTP 认证/拒绝测试 |
| 2. UI 与各 AI 入口接入 | 管理员发布/成员选择/只读状态、个人切换、所有聊天调用者接入 | 组件交互、模型请求参数和现有个人隔离回归 |
| 3. 平台接入与交付验收 | 直连客户端验收、Full 远程调用通道、旧版本处理、备份恢复与使用文档 | 对应运行模式真机/真实服务链路，不能用 Web 测试替代 |

核心通过条件：

1. 管理员建模并授权 A；A 无需填写地址或密钥即可启用并完成真实调用；未授权 B 看不到、猜 ID 也不能调用。
2. A 不能修改/删除共享配置或授权；伪造角色、外部用户 ID、PAT 管理请求均被拒绝。
3. 管理员轮换密钥或修改模型后，A 下一次新调用使用新值；A 的个人库、关闭备份与客户端存储不出现共享凭据。
4. 撤权/暂停/删除后，A 的下一次调用及 Agent 下一轮调用被拒绝；旧界面和缓存无法继续授权，成员收到明确提示。
5. A 启用/关闭 AI、切回个人、重启、换账号/服务器后，选择、调用身份与缓存不串用；关闭总开关时共享调用也被拒绝。
6. 共享模型只处理 A 原本有权读取的上下文，不扩大笔记、附件、工作区或 Token 的权限。
7. 原个人配置 CRUD、模型发现、测试、Anthropic/custom headers、任务 AI、Agent 及个人 Embedding 行为保持有效；共享聊天不偷偷启动共享向量索引。
8. 迁移、配置与授权事务回滚、成员删除、服务重启及全量备份恢复后关系正确；恢复失败保护原数据。
9. Web 和桌面/移动对应模式各自完成共享可见、选择、聊天流式响应、撤权和断网验收；没有设备证据的模式标记待验收。

现有回归入口：`user-preferences.test.ts`、`user-ai-settings-isolation.test.ts`、`ai-config-toggle.test.ts`、`embedding-profile-config.test.ts`、`embedding-user-ai-settings.test.ts`、任务 AI/Agent 相关测试及前端 aiProfiles/AISettingsPanel 测试。新增共享授权、动态撤销及绕路窃取凭据的行为用例。

DCC 重点关联 DCC-006（账号/Profile/服务器隔离）、DCC-008（备份恢复失败保护）、DCC-009（Native 本机模式不得暗中联网）。新增对应行为用例后再登记矩阵；映射检查不能代替行为测试。

## 8. 规模与后续扩展

这是中等规模的权限与配置能力，主要工作在调用链、撤权和平台边界，不宜按“增加一个共享复选框”估算。阶段 1、2 可先完成直连服务器模式闭环；阶段 3 中 Full 的远程调用通道需要独立评估，之后才能给出可靠的全平台工期。

后续有明确需求时，再增加工作区成员动态授权、独立 AI 管理员能力、团队默认模型、调用用量统计/配额及共享 Embedding。当前保持两张表、一个共享选择键和一个聊天解析入口，避免提前建设完整 AI 网关或新的权限框架。
