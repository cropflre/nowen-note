# 静默版本冲突处理设计

## 目标

版本冲突不再向用户显示常驻横幅、首次冲突 toast、确认弹窗或成功提示。系统自动采用服务器当前版本作为正式笔记，并在两侧内容不一致时先把本地内容保存为可恢复的冲突副本。

## 数据流

1. 服务端返回 `VERSION_CONFLICT` 后，离线队列继续保存本地 payload，停止旧 revision 自动重放。
2. 同步引擎读取服务器当前笔记，并使用稳定副本 ID 保存最新一条本地 payload。
3. 副本获得服务器确认后，清理原笔记的冲突队列、草稿和离线快照；服务器当前笔记保持正式版本。
4. 副本写入失败时不清理任何本地恢复数据，后续联网同步继续静默重试。

## 界面边界

- 冲突项目不参与 `OfflineIndicator` 的横幅、详情列表和计数。
- 不再监听冲突事件弹出编辑器 toast。
- 普通离线、非冲突同步失败和长时间同步提示保持现状。

## 验证

- 自动处理只选取每篇笔记最新的冲突队列项，并调用“使用服务器版本”路径。
- 纯冲突状态不产生全局提示；混合状态仍展示非冲突失败。
- 冲突事件不再触发编辑器提示路径。
- 定向 Vitest 与前端构建通过。
