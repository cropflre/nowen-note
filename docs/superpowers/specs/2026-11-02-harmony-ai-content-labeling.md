# 鸿蒙上架：AI 生成内容标识

状态：实现中，未满足送审条件。用户已选择保留 AI，补齐标识、材料和回归后再上架。

## 问题与范围

当前鸿蒙包复用完整前端，存在 AI 对话、写作助手、摘要、图表、协作、日记报告和 Agent。对话复制和部分编辑写入没有保留明确的 AI 生成提示；笔记可以导出 Markdown、Word、PDF 和 PNG/JPG。仅修改商店 AI 声明不能解决生成内容的展示、复制和文件元数据问题。

本任务覆盖实际可达的生成结果及其保存/导出链路。不宣称实现模型服务商的备案、安全评估或第三方认证；不伪造模型输出、签章、截图或检测结果。

## 设计边界

- 标识是来源声明，不是数字签名或内容真实性证明。
- 只标识已知的 AI 输出；手工笔记、用户提问和原样保存的原始输入不自动标为 AI 生成。
- 明确生成结果时使用 `Label: "1"`。不通过猜测文字风格分类。
- 首次生成时记录稳定制作编号。导出时保留制作信息，记录应用的传播信息；不写入令牌、服务器凭据、用户账号或私人联系方式。
- 来源标识随正文持久化、加密、历史和现有同步事务流转，避免另建本机旁路数据库造成跨账号丢失或不同步。Markdown 使用保留注释保存结构化信息和可见文本提示；富文本使用带来源属性的文本标记保存同一信息。
- 格式转换需要双向保留声明；导出从原始权威正文读取来源，不能依赖转换后残留的提示文字猜测。
- 用户明确删除内容时允许删除相应正文；不把来源声明当作权限、同步 ACK 或用户身份依据。
- Agent 批准、应用和持久化收据必须对同一带标识结果验证；不能先确认保存，再另发一次附加写入。旧服务器兼容边界需要明确验证。

## 官方格式

来源：全国网络安全标准化技术委员会秘书处，以及华为开发者文档。

- [TC260 图片文件格式指南](https://www.tc260.org.cn/resources/upload/file/2026/4/9/1775706318096_03%20%E3%80%8A%E7%BD%91%E7%BB%9C%E5%AE%89%E5%85%A8%E6%A0%87%E5%87%86%E5%AE%9E%E8%B7%B5%E6%8C%87%E5%8D%97%E2%80%94%E2%80%94%E4%BA%BA%E5%B7%A5%E6%99%BA%E8%83%BD%E7%94%9F%E6%88%90%E5%90%88%E6%88%90%E5%86%85%E5%AE%B9%E6%A0%87%E8%AF%86%E6%96%B9%E6%B3%95%20%E6%96%87%E4%BB%B6%E5%85%83%E6%95%B0%E6%8D%AE%E9%9A%90%E5%BC%8F%E6%A0%87%E8%AF%86%20%E5%9B%BE%E7%89%87%E6%96%87%E4%BB%B6%E3%80%8B.pdf)：JPEG XMP / PNG 元数据，保持文件可解码且只保留一份当前声明。

元数据字段均为字符串：Label、ContentProducer、ProduceID、ReservedCode1、ContentPropagator、PropagateID、ReservedCode2。应用标识使用公开包名 `com.nowen.note`，不声称它是已申请的监管平台服务商编码。

## 验收计划

1. 结果展示、复制和应用 → 验证手工内容不误标，流式/取消结果有提示，复制与插入保留提示，撤销与失败不产生半次写入。
2. 保存、重开和转换 → 使用真实 Native 数据库/Outbox 以及 Markdown ↔ 富文本转换验证；适用 DCC-002、003、006、009。JSON 序列化单测不能替代这些行为测试。
3. 导出 → 逐一解析 Markdown/YAML、DOCX XML、PDF 信息字典、PNG/JPEG 元数据；核对标识字段、制作编号、可见提示、附件与正文未损坏。分段图片的每一页都应有提示。
4. 发布材料 → 最终候选包的模拟器/真机或云测证据、实际生成结果截图、说明函、隐私政策和用户协议补充条款。材料内容以实际结果为准，未验证项继续阻止送审。
