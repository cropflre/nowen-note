# 富文本粘贴与窗口状态恢复设计

## 目标

1. 从钉钉等支持 HTML 剪贴板的来源粘贴到富文本编辑器时，默认保留编辑器支持的标题、列表、表格、粗体、颜色、字号、图片等源格式。
2. Electron 主窗口在重启和覆盖升级后恢复上次的正常尺寸、位置及最大化状态；显示器布局变化时保证窗口仍可见。

## 根因

- `TiptapEditor` 在 HTML 分支之前检查纯文本是否像 Markdown。钉钉文档中的多条数字列表会达到 Markdown 评分阈值，导致纯文本分支抢先返回，剪贴板里的 HTML 被忽略。
- `electron/main.js` 创建主窗口时固定使用 `1280 × 800`，现有设置中没有窗口状态，也没有任何移动、缩放或退出时的保存逻辑。

## 设计

### 富文本粘贴

新增一个纯函数判断剪贴板中是否存在可用 HTML。只要安全清洗后的内容包含真实 HTML 元素，Markdown 自动识别分支就不得抢占；代码块内粘贴以及现有“复制代码自动形成代码块”规则保持不变，只有纯文本的 Markdown 仍保留现有转换提示。

### 窗口状态

在现有 `settings.json` 增加 `windowState`：保存正常状态下的 `x`、`y`、`width`、`height` 和 `maximized`。设置文件位于持久化用户数据目录，因此覆盖升级不会清空。

窗口创建前根据当前显示器工作区校验保存状态：尺寸至少满足应用最小尺寸；只要与任一显示器工作区有可见交集就原位恢复，否则居中放到主显示器并限制在其工作区内。窗口移动、缩放、最大化变化和关闭时采用短延迟合并写入，避免高频磁盘写入；保存时始终使用 `getNormalBounds()`，不把最大化后的全屏尺寸覆盖掉。

## 验证

- 单元测试覆盖：带数字列表的纯文本和有效 HTML 同时存在时选择 HTML；只有纯文本时仍选择 Markdown；空壳 HTML 不阻断纯文本分支。
- Electron 单元测试覆盖：设置归一化、跨升级持久字段、显示器内恢复、断开显示器回退、最小尺寸和最大化状态。
- 运行相关 Vitest、Node 测试以及前端构建。
