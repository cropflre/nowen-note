# NAS 数据同步到本机与离线使用开发方案

日期：2026-10-27。更新：2026-10-28。状态：首期代码已实现，安装包与 NAS/真机验收待完成。分析基线：`release/v1.5.4` / `92627148`。

本方案依据源码与隔离复现制定；首期实现与自动验证见 [开发验收记录](../../qa/nas-offline-client-2026-10-28.md)。下文保留设计与验收要求，不能将未完成的设备/生产验收视为已通过。

## 1. 目标与交付边界

用户完成一次 NAS 账号连接和数据下载后，客户端即使无法访问 NAS，也能在退出、重启后打开本地笔记和已下载附件，继续编辑；恢复连接后通过现有 Sync V2 同步，另一台设备能读取对应版本。

这里的“NAS 账号”指 NAS 上部署的 Nowen Note 服务账号；“文件”指 Nowen Note 管理的笔记、图片及附件。NAS 任意目录、SMB 挂载、WebDAV 双向镜像和将笔记自动转换成 Word/Markdown 文件不在本次范围内。

首期产品决策：

- 正式支持桌面完整版（Windows/macOS；Linux 使用相同实现但需单独验收）与 Android 的个人空间核心笔记离线闭环。
- 核心范围为普通富文本、Markdown、笔记本/个人知识树、标签与关系，以及这些笔记引用的受管附件。文件内容能离线获取与客户端能预览该格式分别验收。
- 桌面完整版曾选择远程连接的用户，通过现有迁移链路转为本地运行；迁移期间保留原远程入口。
- 真正的 Lite 安装包继续提供在线访问，并明确引导安装完整版、连接原 NAS 后下载。Lite 缺少后端资源，首期不承诺在 Lite 包内完成迁移。保留其原账号配置、缓存和未发送修改，迁移前明确提示先处理待同步修改。
- Web 保留当前浏览器离线缓存能力；iOS/HarmonyOS、共享空间、任务、脑图、独立文件管理及插件数据的完整离线承诺另行验收，不从相同代码或部分已支持推断全部支持。
- 首期默认下载个人空间范围内的核心笔记及其受管附件，不增加按文件夹选择、空间自动淘汰、后台常驻等设置。

## 2. 已核查能力与实际缺口

| 项目 | 当前依据 | 开发结论 |
| --- | --- | --- |
| Sync V2 开关 | `backend/src/sync/flag.ts` 未配置时默认开启，仅 `0`/`false` 显式关闭 | 无需再做“默认开启”；诊断需区分主动关闭、旧服务端不支持和网络失败 |
| 桌面本地模式 | `electron/settings.js`、`electron/main.js`；完整版本地 SQLite、远程连接可选 | 复用本地后端和 Outbox，不另建缓存数据库或同步协议 |
| 完整版旧远程模式的切换 | `sync:start-lite-migration` 完成处仅写 `liteMigrationStatus`；`deriveRuntimeFields` 保留已有 `runtime=remote` | 已用真实 settings 模块与临时目录复现：写入 complete 后仍为 remote。必须修正完成后的持久化切换 |
| 桌面重启入口 | `app.whenReady` 仍用 `currentMode === 'lite'` 决定等待 NAS，窗口地址已使用 `currentRuntime` | 存在启动与窗口选路不一致；需要实际启动失败用例验证，不能仅测试 settings 返回值 |
| Lite 资源 | `electron/builder.lite.base.config.js` 仅带前端，无 backend；`isLiteOnlyBuild()` 检查后端入口 | 有迁移按钮不代表该安装包能执行迁移；入口先检查本地运行能力 |
| Android 本地模式 | `mobileLocalFirstRuntime.ts`、`mobileLocalFirstBridge.ts`、Native SQLite/Filesystem | 复用账号库、Repository 和 Mobile Sync Engine；离线访问不切到独立“仅此设备”空库 |
| 附件完成声明 | `liteMigration.ts` 允许二进制延后；`SyncSettingsTab.tsx` 完成后显示“数据已完整落地” | 分离“本地运行已就绪”与“全部目标附件可离线访问” |
| Android 附件失败 | `mobileSyncEngine.ts` 下载失败写通用 failed；下次仅 pending_download 进入 GET，其余进入上传分支 | 静态代码支持该风险，尚未运行复现；先证明失败后仍 GET，且不得 HEAD/PUT 或误标上传完成 |
| 下载诊断 | 桌面 `/diagnostics` 未给附件下载统计；移动端 pendingAttachments 混合上传、下载及失败 | 不能用统一待处理数判断离线可用；需要按方向和范围统计 |
| 初次全量与恢复 | 桌面 bootstrap 将页游标落库，但 remoteItems 只在内存累计；迁移校验主要是数量和首屏 ID 抽样 | 加强第二页失败、进程重建后的完整性测试；数量/抽样不构成完整正文证明 |
| 登录失效 | `App.tsx` 网络失败可用 cachedUser，明确鉴权失败广播登出；移动 Runtime 依赖 token/账号绑定 | 必须区分本地访问会话与远端同步授权，离线与授权过期分别验证 |

“已复现”仅覆盖设置派生逻辑，其他行为按以上证据级别推进；不据此声称已复现反馈用户的设备问题。

## 3. 用户流程与状态

### 3.1 新安装与已有本地用户

1. 客户端先打开本地空间；用户在现有同步设置连接 NAS 地址并登录 Nowen Note。
2. 显示首次下载阶段：读取目录和笔记 → 写入本机 → 下载附件。允许查看已落地内容，未下载项目显示具体状态。
3. 正文基线完成后显示“笔记已保存到本机”；附件全部就绪后显示“当前个人笔记及附件可离线使用”，同时显示最近核验时间。
4. 断网后直接使用同一账号、同一范围的本地副本；编辑事务提交后显示本地保存/待同步状态。
5. 网络恢复、应用回到前台或用户点击“立即同步”时，由现有引擎继续处理。

连接前已有本地笔记时，保留当前已有对账语义：仅本地存在的内容可能上传；连接入口须明确提示“本机已有笔记也将同步到该账号”。不能无提示把其他账号的数据归入新账号。

### 3.2 已有远程连接用户

- 检测到安装包具备本地后端资源时，显示“下载到本机，支持离线使用”，复用现有迁移 IPC。
- 先核对当前服务器、账号、目标本机数据和未发送修改；迁移前生成并校验本地已有数据的可恢复备份。迁移以原稳定 ID 合并，禁止覆盖整个本地库。
- 正文、关系和必要目录已可靠落库并建立增量基线，才允许设置本地运行。附件可继续后台补齐，但必须显示剩余数量。
- 迁移结果与设置跨 SQLite/settings.json 的提交不是一个事务：先持久化迁移完成记录，再写 settings；下次启动先核对两者，修复“库已完成、设置未切换”，不重复重建账号或基线。
- 重启后先启动本地后端并恢复本地访问会话，NAS 探测只影响同步；不能让 NAS 15 秒超时成为本地使用前置条件。
- 真 Lite 包不展示可执行的本地迁移按钮；明确其在线使用范围和完整版接续路径。不得自动跨应用目录搬库或清除 Lite 缓存。

### 3.3 状态含义

| 展示 | 必须具有的证据 | 允许的操作 |
| --- | --- | --- |
| 正在下载笔记 | 目标账号/范围已确定，完整基线尚未建立 | 查看已有副本、查看进度、重试 |
| 笔记已保存到本机，附件下载中 | 正文与结构基线已落库，仍有目标附件缺失 | 阅读/编辑本地正文；缺失附件提示需下载 |
| 可离线使用（截至某次核验） | 目标范围的有效正文、结构、附件文件均已核验 | 离线重启、读取、编辑 |
| 离线，修改等待同步 | 本地事务与待发送意图已提交 | 本地继续编辑、查看待发送状态 |
| 需要重新登录才能同步 | 远端授权过期；原账号本地空间仍可识别 | 访问已有副本、保留本地修改、重新登录 |
| 部分内容无法下载 | 权限、远端缺文件、校验失败、磁盘不足等明确原因 | 查看失败项、重试；不得显示全部离线就绪 |
| 冲突待处理 | 保留本机和远端版本的冲突记录 | 继续读取可用副本、进入现有冲突中心 |

“可离线使用”与“云端已确认”是独立维度。存在未上传修改或冲突，不代表本地副本不可读取；NAS 后续的新版本也不能由一次旧核验保证已下载。

## 4. 技术设计

### 4.1 数据流与权威源

```text
编辑器 → 现有本地 Repository/内嵌 API → SQLite 业务写入 + Outbox 同事务
                                          ↓
                               现有 Sync V2 推送/拉取
                                          ↓
                                      NAS 服务端

附件：现有 Blob 通道 → 临时文件 → 大小/哈希校验 → 稳定路径 → 本地可用标记
```

本地读取、保存无需等待 NAS 响应；远端权限仍由服务端校验。保留现有 mutationId、版本冲突、墓碑、scope 与协议协商，不用修改时间覆盖双方版本。

### 4.2 离线就绪信息

扩展现有本地 `/api/sync/local/diagnostics` 与移动 `createNativeAdminAdapter` 的等价响应，添加可选 `offline` 字段，沿 `syncLocalApi.ts` 使用统一类型。无需新增 NAS 同步协议或独立下载调度器。

建议响应结构（实施时落实字段名，语义不得弱化）：

```ts
type OfflineReadiness = {
  supported: boolean;
  scopeKey: string;
  contentState: 'not_started' | 'downloading' | 'ready' | 'error' | 'unknown';
  verifiedSequence: number | null;
  verifiedAt: string | null;
  attachments: {
    total: number | null;
    available: number | null;
    pendingDownloads: number | null;
    failedDownloads: number | null;
    missingFiles: number | null;
  };
  fullyAvailable: boolean;
  verificationPending: boolean;
};
```

- 外层 Profile 身份与 `scopeKey` 共同确定范围；接口必须受现有本地会话鉴权。关闭同步后仍按当前已选账号读取本地状态，不能仅查 enabled Profile 后把本地统计变成 0。
- 原诊断字段保留。旧端缺少 offline 字段时显示“尚未核验”；未知总数使用 null，不伪造 0 或百分比。同步授权、待上传数、冲突继续使用现有字段。
- fullyAvailable 仅在受支持范围、正文基线已确认、无待核验项，且目标附件全部实际可用时为 true。失败项即使不在调度队列里，也阻止完整就绪声明。
- 复用现有 Profile/bootstrap 状态和本地 runtime meta 保存范围化核验版本；确需新增持久化结构时使用增量迁移，实施时按最新 schema 分配版本，不在本计划预占迁移编号。
- 接收新正文/附件版本、发现文件缺失或校验失败时及时使相关核验失效。保留“最近一次核验”信息，不能继续用旧 ready 表示新版本已完整下载。
- 不在 5 秒轮询中逐项读盘并计算所有哈希。下载完成时校验；启动时以有界批次检查文件存在和大小；用户打开时复核，发现损坏重新排队。核验未完成期间明确显示待核验。

### 4.3 全量基线与断点恢复

- 完整基线必须遍历约定快照高水位的全部分页，校验正文格式和必要实体关系，再补齐窗口期增量；缺少正文与合法空正文分开处理。
- 对未能持久化页 payload 的桌面 bootstrap，首期采用重启后从首屏重新读取完整快照，避免仅凭已落库游标跳过内存中遗失的前页。除非失败用例证明有必要，不新增通用 staging 框架。
- Lite 迁移已经逐页应用并持久化游标，继续复用；应用成功后才能推进对应游标。重试必须保护本地未发送编辑和冲突，不直接以远端 upsert 覆盖。
- 初次同步期间新建/修改也必须可恢复。特别检查 bootstrap ready 前未生成 Outbox 的窗口：若当前最终状态扫描存在遗漏，补最小持久化意图/对账处理，并以崩溃重建验证。
- 数量和 ID 抽样保留作诊断辅助；离线就绪的依据是完整分页验证和有效落库记录。未知实体、解析失败和数据库失败阻止基线就绪或游标推进。

### 4.4 附件与重试

- 复用桌面 `sync/blob.ts`、`sync/attachments.ts` 与移动 `mobileSyncEngine.ts`、`nativeAttachmentStore.ts`；统计只包含选定账号、个人 scope 及目标笔记引用的受管附件。
- 修正移动失败重试方向：优先复用现有 available/localPath 与文件实际存在性判定；本机无有效二进制时始终下载，只有本地有效文件可证明存在时才允许上传。若现有字段无法可靠区分，再增加持久化方向字段及旧数据回填，不新增第二条传输队列。
- 已标 failed 的旧记录按本地文件存在性恢复方向；错误文本不得充当方向标记。远端 HEAD 成功不能证明本地可离线使用。
- 文件下载先写临时路径，校验大小/哈希后发布，最后标记 available。校验失败、磁盘不足、写库失败均保留可解释的失败状态；重试不得破坏已有有效文件。
- 缺失/403/404 不等于用户删除；失败项保留并提供重试，不无限空转。复用已有并发、退避与调度唤醒，应用重启后可继续。
- 不因单轮批量上限、待上传队列为空或引擎 idle 而宣布下载完成；有更多待下载项时必须继续调度，全部失败时执行退避。
- 大附件与整库下载不能将全部二进制累计在内存。先测现有 Buffer/Blob 路径峰值；若单文件无法在目标设备可靠下载，首期必须采用可行的流式落盘或明确展示格式/大小限制，禁止静默遗漏后显示完整就绪。

### 4.5 本地访问与远端授权

- 桌面继续使用独立本地后端会话；NAS 凭据失效只暂停远端通信，不使本地登录失效。迁移切换必须重新取得本地凭据，不能把远端 token 发给 localhost 当成本地身份。
- Android 保存最后一次已成功绑定的服务器、账号与库映射，使离线打开原账号库不依赖一次成功的 `/me`。远端凭据与本地身份分离；token 更新不改变 Profile、库名和队列归属。
- NAS 不可达与 token 过期时保留本地空间和修改，提示重新认证后继续同步；不能通过忽略服务端 401 或取消服务端校验实现“离线登录”。
- 主动退出/切换账号与临时授权失效分开处理。主动退出后原账号副本留存但不自动向新账号开放；重新进入需按既有账号绑定规则确认身份。独立“仅此设备”库不能被用作原账号离线副本。
- 明确账号禁用、会话撤销、权限撤销时停止相关远端传输，沿既有恢复/只读策略处理，不能以离线访问为由继续获权。共享范围不纳入首期完整承诺。
- 加密正文与附件保持原有保护格式；不额外保存明文密钥、密码、Token 日志。能否离线解锁依据现有密钥可用性独立展示，不承诺绕过密码或权限。

### 4.6 兼容、发布与回退

- 新字段仅扩展本地管理响应，未知字段对旧客户端无影响；NAS 继续使用现有实体集合和能力协商。旧服务端不支持核心同步时保留原在线方式并说明升级要求。
- 目录/结构能力协商失败时不能声称完整个人空间离线就绪；允许明确标注已下载笔记的受限访问。代理返回 HTML、401、非法 JSON 与超时分别诊断。
- settings 与数据库增量迁移均保留旧数据和稳定身份；迁移备份验证失败时不切换运行时。迁移失败仅允许重试或继续原访问，不以清库解决。
- 出现同步问题优先停止远端调度、保留本地编辑；已有本地未上传修改时，禁止直接降级到旧远程客户端后覆盖本地数据。
- 桌面产物验证必须覆盖后端、数据库原生模块、前端离线资源及本地附件路径；完整版与 Lite 独立安装目录、更新通道保持现状。
