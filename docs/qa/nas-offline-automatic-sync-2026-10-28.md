# NAS 自动下载与离线同步补充验收

日期：2026-10-28。代码基于 `ab57a010` 后的实现；验收时为未提交工作区，提交记录以 Git 历史为准。未推送或发布。客户端版本字段仍为 1.5.3；分支为 `release/v1.5.4`。

## 用户流程

登录 NAS → 自动下载笔记与受管附件 → 自动使用本地副本 → 断网继续读写 → 恢复连接后后台自动回传。首次下载需要联网；失败自动重试。本机尚未上传的旧版修改继续保留，不能直接绕过待同步队列建立基线。真正缺少本地后端的 Lite 包仍需安装完整版。

桌面首次建立副本时暂不开放编辑器，防止用户继续写到旧的远端运行时；完成后自动刷新到本地地址和本地凭据。后续启动直接打开本机数据，不等待 NAS。远端授权失效与断网分别处理，授权失效仍可能需要重新登录。

## 修复与失败复现

- 原桌面入口需要打开设置并手动开始迁移，现改为登录后自动执行；遇到网络中断自动重试，无需点击按钮。
- 新增附件 UI 补测在源码版及 macOS 测试包复现文本预览 HTTP 404。本地存在附件元数据，但没有文件，路径仍为 `pending-sync:...`。
- 新增 DCC-003 回归先失败：初次下载未调用任何 blob 下载，证明不是预览断言或缓存问题。
- 修复远端附件元数据落库后的下载登记，并在下载完成时将占位路径替换成正常本地路径。相同元数据重放保留已下载文件，不重复排队。
- 保留的旧版离线写入在建立基线前主动重放，网络恢复后继续尝试；不能仅显示“等待上传”却不再执行上传。
- 迁移完成必须同时满足 HTTP 成功、来源 URL 一致及 Profile 有效。切换 NAS 被拒绝时，旧来源、旧 Profile 和已完成副本保持不变，不以错误响应里的旧完成记录确认新来源。
- 已下载副本的退出登录按本地运行时处理，保留明确退出意图；重开不能重新恢复旧账号。自动首次交接仅在同一会话内清除该登录偏好。
- 对旧版遗留冲突/失败队列显示保留数量，提供本机导出和重新尝试。导出不记录正文到日志；重试不删除队列，版本冲突仍保留，不带未确认写入切换基线。

## 实际验证

使用合成账号、临时数据库和文件；NAS 替身运行生产鉴权、笔记、上传与 Sync V2 路由，仅允许回环访问。桌面隔离用户目录及发现功能；Android 使用独立包名 `com.nowen.note.offlineacceptance`。未接触真实用户笔记或 NAS。

| 环境/场景 | 实际结果 |
| --- | --- |
| macOS arm64 源码桌面 | 登录后自动下载并进入本地工作区；未打开设置、点击迁移或手动重启 |
| 源码桌面首次下载中断 | 注入一次快照 HTTP 503，自动重试后完成首次下载，无按钮操作 |
| macOS arm64 未签名测试包 | 自动下载、首次中断重试、离线重开、未读正文、文本及 PNG 首次离线预览通过 |
| 桌面离线编辑回传 | 编辑提交本地、再次退出重开保留，NAS 恢复后无需重启/点同步即回传；独立鉴权读取服务端正文一致 |
| 桌面账号退出与重开 | 最新源码及 macOS 测试包均通过：首次 NAS 登录意图可自动交接；用户明确退出后完整重开保持登录页，不恢复旧本地账号 |
| Android 16 / API 36 模拟器新版 debug APK | 登录后笔记和附件自动下载；NAS 停止且移除 adb 转发、强杀重开后，未读正文、文本和 PNG 首次离线预览通过 |
| Android 编辑持久化与回传 | 实际原生 SQLite 保存正文且 Outbox 保留待同步项；再次强杀重开仍存在，恢复服务后服务端读取一致 |

Android 初次复测在并发构建期间等待笔记列表超时；没有将其计为通过。构建结束后的完整重跑通过，原始失败与重跑过程见本机执行日志。旧版 APK 的通过结果没有替代本次新版 APK 验收。

后续退出/来源核验与旧队列恢复补强针对桌面；没有将前一轮 Android APK 的结果声称为这些后续修改的新包验收。新增非桌面桥回归确认 Android/Web 继续使用既有工作区。

## 回归与限制

- DCC 映射：12 条不变量、213 个引用通过。
- 前端：34 个文件、277 项通过；Electron：4 个文件、25 项通过。退出登录、NAS 来源拒绝及真实旧队列导出/重试均有先失败再修复的回归。Web/Android 无桌面桥时直接使用原有工作区的边界测试通过。
- 导航组件补充回归 9 项通过，包含已迁移本地运行时退出时关闭自动登录；相关新增文件的范围 lint 通过。
- 后端完整门禁现已通过：32 个文件、480 项，包括全部 Sync V2、多端、附件与离线就绪回归。
- 此前 `note-delete-attachments.test.ts` 的超时定位为 33,000 篇笔记压力用例。独立完整执行 13 项通过，约 40 秒；串行门禁中的压力用例约 37.2 秒，通过原有 120 秒上限。未减少数据量、删除用例或放宽门禁。沙箱端口限制导致的一次 `listen EPERM` 另行处理后重跑通过，没有把该环境失败算作产品通过。
- 前后端类型/构建、Android Gradle 构建及未签名 macOS 测试包构建通过。
- 真实 NAS/反代、实体手机、Windows 和正式签名安装包未验证。10 GiB 容量样本沿用首轮记录，本轮没有重复声称手机通过 10 GiB。
- 普通文本与 PNG 的预览通过，不代表所有附件格式均已验收；共享空间、独立文件管理、任务及脑图的完整离线承诺仍不在本次范围内。

```bash
node scripts/nas-offline-acceptance.mjs --packaged --interrupt-first-download
node scripts/nas-offline-android-acceptance.mjs emulator-5580
```
