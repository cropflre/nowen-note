## AI 快记的数据与权限回归

- 生成接口不写笔记；只读取显式项目与 Skill 范围，拒绝跨账号、错误目录、回收站、整篇/局部加密内容与密码目录。未选项目时不检索其他笔记。
- 保存调用现有 `api.createNote` / `api.createNotebook`，沿用各平台持久化与 Outbox，不把 AI 回复当作保存成功。原始输入随生成结果保存；来源保留笔记身份链接。
- 草稿按服务器、账号和工作区保存在当前设备；账号切换丢弃迟到 AI 响应。保存失败保留稳定 ID 和原请求重试；丢失响应时只接受内容、标题、目录和格式完全一致的现存笔记。损坏旧草稿不会被覆盖。
- 涉及 DCC-002/003/006/010/011：已有离线队列与笔记保存回归，新增草稿/重试及账号切换测试；认证续期不得将旧请求重放到新账号，迟到续期不得覆盖或清除新凭据。
- 浏览器使用隔离 QA 数据库与本机 OpenAI 兼容测试服务，真实调用生成路由和笔记保存/读取 API；不访问用户笔记，也不调用收费模型。覆盖无配置的三步流程、已绑定目录 Skill 的自动匹配和项目来源、AI 失败后直接保存、320/390/1280px 及 480px 短屏。

## 问题与实现

- 文件中心默认卡片最小宽度 170px，手机通常只能展示一列；搜索和操作争抢同一行。手机改为两列可收缩卡片，减少预览高度和内边距，搜索独占一行，面包屑单行横向滚动，筛选字段允许收缩。手机筛选区最多占半屏并可独立滚动，保留文件区空间。
- AI 会话栏默认展开 256px，挤压手机聊天区；运行时注入的模型选择器还会进一步挤压标题。手机默认关闭会话栏，打开为覆盖式抽屉，支持遮罩、关闭按钮、Escape 和移动端返回处理；选中会话后关闭。模型选择器放在手机标题栏第二行，使用明确的标题栏标记挂载。压缩留白，首次默认收起诊断详情，保留已有展开偏好；知识库选择菜单宽度受视口限制。长代码/表格用例还复现了滚动容器默认 `display: table` 将答案撑至 856px 的问题；仅在聊天消息区改为 block，让宽内容在自身区域内滚动。
- 用户卡片在同一行排列头像、详情和四个按钮，手机详情区域过窄。手机把按钮排到信息下方，搜索和筛选分行，移除手机列表内的第二层纵向滚动；管理弹窗受动态视口高度限制，正文独立滚动以便触达底部操作。
- 保留现有按钮至少 36px 的手机触控下限；不采用全局缩放或全局缩小字体。桌面继续使用侧栏与原有信息架构。

## 回归方法

使用已有 `scripts/run-files-assets-qa-server.mjs` / `backend/scripts/files-assets-qa-server.mjs`，该服务只创建临时 QA 数据库及附件目录，端口 4197。不得指向用户生产数据库。

```sh
# Node ABI 与 backend better-sqlite3 匹配时，可由 Playwright 自动启动隔离服务。
cd frontend
npm run build
npx playwright test --config playwright.mobile-layout.config.ts
npm run test:run -- src/lib/__tests__/aiCollaboration.test.ts src/components/__tests__/AICollaborationDialog.test.tsx src/lib/__tests__/authSession.test.ts src/i18n/__tests__/releaseI18nCoverage.test.ts src/lib/__tests__/offlineQueue.test.ts src/lib/__tests__/noteSyncSafety.test.ts src/lib/__tests__/noteSyncSafety.integration.test.ts src/components/fileExplorer/__tests__/FileExplorer.scope.test.tsx src/components/__tests__/FileManagerPublicOriginContract.test.ts src/lib/__tests__/aiChatLayoutContract.test.ts src/lib/__tests__/accountLoginSwitch.test.ts src/lib/__tests__/startupChunkingContract.test.ts
```

本机原生依赖为 Electron ABI 130，系统 Node 为 ABI 137；本次使用匹配的 Electron-as-Node 启动相同隔离服务，再由 Playwright 复用，未重建原生依赖：

```sh
# 从仓库根目录运行；另一个终端运行上面的前端检查。
ELECTRON_RUN_AS_NODE=1 ./node_modules/.bin/electron scripts/run-files-assets-qa-server.mjs
```

浏览器覆盖 Chromium 320 / 390 / 430 / 1280px，手机触控模拟；另将用户弹窗高度降至 480px。断言包括双列网格、长文件名、筛选控件与列表操作边界、面包屑单行可达、长对话标题和模型选择器布局、宽代码/表格、抽屉开关不压缩输入框、长用户名/邮箱、四项用户操作和短屏弹窗的底部按钮。长对话与用户信息仅在测试请求响应中替换，不写入用户数据。

截图输出：`frontend/node_modules/.cache/mobile-layout-results/`（网格、列表、AI、用户卡片与短屏弹窗）。

## 日期按钮点击未弹出选择器

2026-10-16 用户再次反馈桌面端点击“选择日期”仅有焦点边框，没有日历。复现截图也未显示选择器。此前测试点击后使用 `fill` 设置日期，只证明输入值能够变化，未覆盖原生选择器的打开。

修复在受信任的点击事件内调用原生 `showPicker()`，并将 WebKit 原生日历图标的命中区域扩展到整个按钮，保持不支持或拒绝 picker API 时仍可走原生指示器。保留按钮边界、日期格式与日记导航语义。

浏览器测试增加原生 `showPicker` 成功调用断言（调用真实 API，不替换成假实现），保存打开日历时的截图，并验证重复打开、取消和原有日期变更后的布局。修复前桌面用例失败：成功打开次数为 0。已核对桌面原生日历弹层截图，并通过原生日历的方向键与 Enter 实际选日，确认日记标题随选定日期切换。前端构建、16 项相关测试、8 项浏览器回归与定向 ESLint 通过；修复前打开次数为 0 的用例修复后通过。iOS、Android / WebView 真机验收不能由 Chromium 结果代替。
