# Agent 任务逐条编辑与批量创建验收（2026-10-27）

基线为 `release/v1.5.4` 的 `ef88ba34ee6aca4d9a85426f13678b00a1888b29`，实现位于独立工作区 `codex/agent-task-review-20261027`。没有切换主目录分支、修改其未提交内容或使用私人笔记。测试使用隔离数据库和合成账户。

## 实现与安全边界

- 逐条编辑任务标题、描述、优先级、开始/截止日期和时间、重复规则及结束条件；取消勾选可排除，重新勾选可恢复。
- 本地编辑期间禁止创建，先点击「核查任务修改」，由服务端返回新预览，再单独确认创建。可放弃本地修改恢复服务器预览。
- 新增 `POST /api/agent/workflows/:id/tasks`，要求当前审批令牌、相同用户/工作区、有效来源与未完成任务动作。所有原始候选 ID 必须恰好提交一次，不允许新增身份、修改项目/作用域或绕过去重。
- 核查与创建共用原 task composer 的日期、周期、项目及去重校验。核查只替换内存草稿并事务性换发审批令牌，不调用模型、不创建资源、不延长原会话有效期。旧令牌立即失效。
- 排除项不进入任务业务写入，排除全部任务时记录空任务结果，不创建 composer batch；其他笔记/外部动作继续要求正常审批。选中项空标题拒绝，已排除项可保留空标题。
- 核查响应丢失时只 GET 核对状态，不重放修改。账号切换后的迟到结果不更新新账号。任务已创建后不能通过原提案再次修改；部分失败经显式重试后，可调整尚未创建的任务。
- 沿用原任务事务、结果身份和 Outbox（DCC-002），原用户/工作区边界（DCC-006）；无需数据库迁移或新同步队列。

## 百炼真实模型：已跑通，稳定性验收未通过

使用仓库外临时配置连接 `https://dashscope.aliyuncs.com/compatible-mode/v1`，固定模型 `deepseek-v4.1-flash-1017`。场景从两篇合成笔记生成三项任务，先检查模型没有捏造日期；用户在实际界面修改第一项标题、描述、优先级、日期、每两周重复及总次数，排除第三项，核查后只创建两项，并关联原来源笔记。另验证旧审批令牌与重复审批拒绝，重启后任务记录完全一致。

- 首次场景 **1/1 成功**，约 1.1 分钟，完整走过真实模型、界面编辑、审批和保存。证据见 `initial-live-success.json`。该次在随后「排除项允许空标题」的校验边界完善之前，不能当成最终源码的全部验收。
- 最终源码的两次普通复测均为 `MODEL_TIMEOUT`，都在两次检索后、进入审批前失败。
- 最终源码的另一次元数据诊断复测也为 `MODEL_TIMEOUT`。确认检索已返回两篇来源，只有 237 字符上下文；第二次模型请求约 5.951 秒返回 HTTP 200 / SSE 响应头，但响应体未在单次 45 秒内完成。没有证据将原因单独归为服务端或网络。
- 一次临时诊断脚本在请求发出前因 URL 对象处理错误退出，修正后另行运行；该次不计入真实供应商成功/超时数。诊断代码没有进入产品源码。

因此本轮实际调用结果为 **1 次成功、3 次超时**，最终源码真实模型稳定性门槛仍未通过。没有调整测试输入、放宽 45 秒请求/120 秒工作流预算或删除失败记录来获得通过。失败用例未发送创建审批；不把响应头 200 当成提案或业务成功。

机器可读记录、成功场景任务与失败状态见 [acceptance.json](artifacts/agent-task-review/2026-10-27/acceptance.json)。仅包含合成内容、模型信息和有界诊断元数据。凭据只保存在仓库外 0600 文件中；检查源码、日志和证据未发现凭据后，已删除整个临时凭据及诊断目录。没有保存到日常 AI 配置。
