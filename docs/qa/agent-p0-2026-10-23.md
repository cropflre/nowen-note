## Markdown Redo 失败原因与修正

Playwright `ControlOrMeta+Shift+z` 会发送 `shiftKey=true`、`key="z"`。在 Linux CodeMirror 键位解析中，小写字符可先命中 Undo：如果还有一条本地编辑历史，就会再次撤销，而不是 Redo。原 CI 的失败正文同时失去了 Agent 修改和此前的本地输入，与此一致。

用项目安装的 CodeMirror、Playwright Chromium 和两个独立历史步骤复现，覆盖 `navigator.platform = "Linux x86_64"`：

| 输入序列（此前均已 Undo 一次） | 结果 |
| --- | --- |
| `Control+Shift+z` | `original`，错误地再次 Undo |
| `Control+Shift+Z` | `improved local`，正确 Redo 并保留本地输入 |

E2E 改为真实 Shift 字符对应的大写 `Z`，并在 Undo 后明确断言本地输入仍在。未修改编辑器产品代码。另在临时测试副本中模拟 Linux platform、显式使用 Control 键跑完整的两个编辑器场景，2/2 通过（16.5 秒）。这是 macOS Chromium 上的 Linux 键位模拟，**不等于 Linux 主机、Windows Electron 或系统键盘真机验收**。

## 旧聊天兼容与排序修复

新增真实路由、磁盘 SQLite、生产前端的浏览器回归；模型端使用受控 SSE 测试服务，以便精确在回答尚未完成时切换标签。

- 已有问题/回答可加载，Q&A → Agent → Q&A 后输入草稿、历史均保留。
- 新问题发送时携带旧聊天历史，且只请求一次模型。
- 在 Agent 标签停留期间完成流式回答；四条消息全部入库，顺序为旧问题、旧回答、新问题、新回答。
- 切回 Q&A 展示完整回答；停止并重新启动后端，重新打开聊天后历史仍在。

测试实际暴露了旧路径的同秒排序问题：`createdAt` 精度为秒，而前端消息 ID 分别以 `u-`、`a-` 开头，按 ID 排序会让同秒的回答先于问题。当前聊天路由直接使用 SQLite；修复以 SQLite `rowid` 作为时间相同时的插入顺序，并同步用于会话预览、最近 N 条查询、200 条保留上限裁剪。无 schema 迁移，不改模型调用或历史写入路径，不宣称 PostgreSQL 聊天 Runtime 验收。

新增两个后端回归覆盖同秒消息、重开数据库、最近三条分页、最新消息预览、保留上限裁剪及跨用户会话读取拒绝（DCC-006）。已准备将该测试文件和相关路径触发条件加入 CI；工作流补丁因当前推送凭据缺少 `workflow` 权限而保留在本地，尚未推送。
