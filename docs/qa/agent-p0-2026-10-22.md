## 重启、同步和 PostgreSQL

**进程重启：** Playwright 停止生产后端进程，再以相同隔离磁盘数据库启动新进程。已保存正文仍一致；另一个待审批提案恢复为 `interrupted / SERVER_RESTARTED`，旧凭证返回 409，原文不变。该证据不等于打包客户端验收。

**独立数据库：** 两种格式分别完成实际链路：A/B 使用独立磁盘 SQLite，通过产品 Sync V2 HTTP 路由获得同一笔记；审批后经 NativeLocalRepository 写入 A 的正文和 Outbox。未推送时服务端保存核验返回 409，B 保留旧正文。关闭重开 A 后正文和原 mutationId 保留。服务端应用成功但 ACK 缺失版本证据时，A 保持 pending。此时 Agent 核验服务端正文成功也不清除 A 的 Outbox。重试取得有效 ACK 后队列出队、收据 confirmed，A/B/服务端正文一致，服务端版本未重复推进。

整个既有多设备测试文件 77 项全部通过，新增一个测试内覆盖两种格式。这是产品仓储/同步引擎和独立数据库集成验证，原生平台由测试 SQLite adapter 承载，**不是两台物理设备或 Android 插件桥验收**。

**PostgreSQL：** 使用专用、仅监听 127.0.0.1 的临时 PostgreSQL 16.15 容器，真实迁移/约束测试通过后已移除容器。未访问已有 PG 数据；schema 兼容不代表启用了完整 PG Agent Runtime，当前产品运行时仍使用 SQLite。
