# 多服务端配置与本地 → NAS 安全迁移

## 产品入口

服务端管理不再作为左侧栏中的常驻业务模块展示。

用户通过以下场景进入：

- 点击账号入口，打开「连接与账号」；
- 本地模式下点击「连接 NAS / 云端」快捷入口；
- 在连接配置中进入一次性数据迁移流程。

这样可以让笔记、日记、待办等高频模块保持清晰，同时保留自托管、NAS 和多实例用户需要的高级能力。

## 功能边界

「连接与账号」流程包含三类互不等价的操作：

- **切换服务器**：只改变当前客户端连接的实例与账号，不复制数据。
- **迁移数据**：把一个实例的个人空间一次性复制到另一个实例。
- **导入备份**：从用户选择的备份文件恢复数据，继续使用数据管理模块完成。

迁移不是双向同步。完成本地 → NAS 迁移后，推荐让电脑、手机和平板统一连接 NAS 实例；本地实例只保留为只读备份或应急恢复源。

旧版「切换到云端」轻量迁移弹窗和对应迁移引擎已经移除，避免与迁移协议 v2、服务端档案及系统安全凭据形成两套并行实现。

## 多服务端配置

每条配置包含：

- 自定义名称；
- 服务端 URL；
- 类型（本地、NAS、远程、演示）；
- 当前账号；
- 连接状态；
- 最近检测和最近使用时间；
- 登录凭据状态。

档案 JSON 只保存非敏感元数据。桌面端勾选记住凭据后，密码和令牌仅进入系统安全存储；Web 端不持久化秘密。切换前会显示目标服务器、账号和未同步队列风险，并要求明确确认。

## 移动端自动选择连接地址（v1.5.1）

同一台 NAS 的公网和局域网地址属于同一个服务端配置。原生移动端默认启用自动选路：

- 已保存地址可达时继续使用；移动网络始终使用已保存地址。
- Wi-Fi 下已保存地址不可达时，通过 `_nowen-note._tcp.local.` 发现局域网地址。
- 首次身份必须通过已保存地址的 `/api/version` 确认；发现地址返回的 `serverInstanceId` 完全相同时才切换。没有身份或身份不一致时保留离线能力，不自动连接其他实例。
- 离开 Wi-Fi、网络变化和回到前台时重新选路；局域网地址不持久化。传输失败后限速重试，允许重新发现 DHCP 变化后的地址。
- 仅切换 HTTP、附件和 WebSocket 的访问路径。账号、Token、SyncProfile、SQLite、同步游标和待传队列保持原归属，不重新登录或 Bootstrap。

「设置 → 数据与同步 → 服务器连接」显示当前路径、常用地址和服务器身份，并可关闭自动选择。正常切换不弹 Toast。

探测只请求公开版本接口，不携带登录凭据、不跟随重定向。Capacitor 原生 HTTP 代理不完全支持 fetch 的重定向语义，因此探测使用原始 Web fetch；后端已允许默认原生来源。若代理拦截 CORS、路由器隔离 Wi-Fi 客户端或过滤 mDNS，则无法自动发现，仍可使用手填地址或域名加 Split DNS。

验收时使用同一台服务器的公网入口和 LAN 入口：先在移动网络连接一次确认身份，再进入无法访问公网入口的家中 Wi-Fi，确认自动恢复同步；随后离开 Wi-Fi，确认恢复公网路径。测试还应包含同网段另一台不同身份的服务、LAN IP 变化、关闭自动选择和未同步编辑。LAN 可达而公网在 Wi-Fi 不可达强烈指向 NAT 回环或路由配置问题，单凭这一项不能排除 DNS、防火墙等原因。

## 迁移协议 v2

接口前缀：

```text
/api/user-migration/v2
```

安全流程：

1. `GET /preflight` 扫描笔记本、笔记、标签、历史版本、任务和附件。
2. `POST /target-preview` 检查历史迁移记录和源端变化。
3. `POST /source-backup` 在源实例的数据目录创建 ZIP 安全备份。
4. `GET /export` 取得带快照哈希的数据集。
5. `POST /import` 事务导入元数据并返回 ID 映射。
6. 逐个下载和上传附件；两端都校验大小与 SHA-256。
7. `POST /rewrite` 重写笔记和任务中的附件引用。
8. `POST /complete` 在目标端重新读取所有附件，复核数量、大小和 SHA-256。
9. 成功后切换客户端到目标服务器。

## 冲突策略

- **跳过已有**：已迁移项目保留目标版本，只补充新内容。
- **更新迁移副本**：只更新历史迁移创建且仍可追踪的副本，不覆盖目标端原生内容。
- **保留两份**：源内容变化时新建带“迁移副本”后缀的内容。

服务端通过以下组合追踪源项目：

```text
targetUserId + sourceInstanceId + sourceUserId + entityType + sourceId
```

因此重复执行同一快照会复用目标 ID，不会静默生成重复副本。

## 中断、续传和撤销

客户端把迁移 ID、源快照、ID 映射和已完成附件记录写入本地 checkpoint。中断后使用相同源、目标和策略再次执行时：

- 元数据导入按迁移台账幂等复用；
- 已完成且哈希一致的附件跳过传输；
- 未完成附件从断点继续；
- 最后仍执行目标端完整校验。

失败后可以调用 `POST /rollback`。回滚只删除该迁移 ID 创建并可追踪的目标副本，不影响源端数据、源端 ZIP 备份或目标端原生内容。

## 备份位置

默认目录：

```text
<ELECTRON_USER_DATA>/migration-backups/
```

非 Electron 部署回退到：

```text
<cwd>/data/migration-backups/
```

备份包含 `manifest.json`、`data.json` 和笔记/任务附件二进制。源端存在物理文件缺失时，自动备份和迁移都会被阻止，避免生成看似成功但实际残缺的数据副本。
