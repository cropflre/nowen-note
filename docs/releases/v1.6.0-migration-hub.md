# v1.6.0 — AI Migration Hub（开发阶段）

新增统一导入与迁移中心：NMF v1、持久化任务、通用文件与安全 ZIP 适配、预览与登录会话审批、后台分批写入、迁移历史/报告、失败重试、暂停/取消及未改动结果的安全撤销。现有 MCP、REST 和 TypeScript SDK 共享同一任务服务，MCP 不提供批准工具。

Added a unified migration hub with NMF v1, persistent jobs, generic files and bounded streaming ZIP ingestion, preview-bound session approval, background writes, history/reports, retry/pause/cancel and guarded undo. MCP, REST and the TypeScript SDK use the same service; MCP cannot approve imports.

Phase 1 新增 Notion Markdown/HTML/CSV 与思源原生 ZIP → NMF 适配、4 MiB 分块及 SHA-256 校验的断点上传，以及预览中的跳过／保留已有／创建副本决策。Notion、思源稳定 ID 可跨导出识别迁移中心已有来源，变化项需处理并重新审批，不覆盖已有笔记。浏览器重新选择同一文件、stdio MCP 再次调用同一任务可续传；SDK 提供显式会话方法。源 ZIP 上限仍为 512 MiB。

Phase 1 adds Notion Markdown/HTML/CSV and Siyuan native ZIP adapters to NMF, resumable 4 MiB uploads with chunk and full-file SHA-256 checks, and per-item skip / keep existing / create copy decisions. Stable Notion and Siyuan IDs detect sources previously imported through the hub across exports; changes require a decision and a new approval, with no overwrite. Browser file reselection and repeated stdio MCP calls can resume the same job; the SDK exposes explicit session methods. Source ZIPs remain limited to 512 MiB.

Notion CSV 属性只作为有界来源元数据暂存并报告字段名，不写入笔记属性或数据库；思源按 Markdown 转换器降级，嵌套块引用保留来源链接。这些适配不承诺平台无损、评论／历史／权限或加密解密。旧平台导入入口和历史保留。

Notion CSV values are bounded source metadata for staging and field-name reporting, not imported note properties or databases. Siyuan uses the Markdown converter and retains source links for nested block references. These adapters do not promise lossless platform restoration, comments/history/permissions or decryption. Existing importers and their history remain available.

Phase 2 增加版本化 Source Adapter 扩展规范和可发现的来源能力说明、华为 TXT/HTML 导出文件适配，以及按 AI 客户端生成连接配置、复制迁移指令与只读接入检查。配置使用凭据占位符或环境变量引用，并区分 Codex TOML、已知 JSON 格式与未核验宿主的通用模板。接入检查不替代真实客户端的列工具、能力查询和文件访问验收，也不会自动连接来源账号；华为适配不读取云数据或执行手写 OCR。

Phase 2 adds a versioned Source Adapter contract and a discoverable source capability catalog, Huawei TXT/HTML export-file handling, client-specific connection examples, a copyable migration prompt and read-only setup checks. Configuration uses credential placeholders or environment-variable references and distinguishes Codex TOML, documented JSON forms and generic templates for unverified hosts. Setup checks do not replace listing tools, querying capabilities and verifying file access in the real client, nor do they connect source-platform accounts automatically. The Huawei adapter does not access cloud data or perform handwriting OCR.

真实 HTTP 和独立原生 SQLite 客户端的大包同步自动化与生产验收分开记录。真实 NAS、代理／S3、物理 Android、安装包及第三方 AI 客户端仍需环境验收。此文为开发草稿，不表示已经发布。详见 [技术设计](../architecture/ai-migration-hub.md)、[P0 验证记录](../qa/ai-migration-hub-2026-10-29.md)、[Phase 1 验证记录](../qa/ai-migration-hub-phase1-2026-10-29.md) 和 [Phase 2 验证记录](../qa/ai-migration-hub-phase2-2026-10-29.md)。

Large-package sync automation with real HTTP and independent native SQLite clients is separate from production acceptance. Real NAS, proxy/S3, physical Android, packaged apps and third-party AI clients still require environment testing. This is a development draft, not a release announcement; see the [Phase 1](../qa/ai-migration-hub-phase1-2026-10-29.md) and [Phase 2](../qa/ai-migration-hub-phase2-2026-10-29.md) validation records.

后续 [发布前隔离验收](../qa/ai-migration-hub-release-2026-10-29.md) 已完成 Claude Code CLI 的合成模型双传输接入、实际 P0/P1 数据升级、Linux 代理大包崩溃恢复和本地对象协议/补偿测试。512MiB 容器触及内存限制；S3rver 不校验 V4 密钥签名。它们不等于 NAS 长稳、真实云 S3 或所有 AI 宿主通过。app/backend 版本仍为 1.5.3，正式 v1.6.0 版本与产物尚未生成。

Subsequent isolated checks cover Claude Code CLI with a synthetic model over both transports, actual P0/P1 upgrades, Linux proxy/crash recovery and local object-protocol compensation. The 512MiB container reached memory pressure, and S3rver does not validate V4 signing secrets. These results do not certify NAS stability, real cloud S3 or every AI host. App/backend versions remain 1.5.3; formal v1.6.0 versions and artifacts have not been produced.
