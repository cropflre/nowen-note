# 1.6.0 扩展体验：迁移与回滚

适用于扩展中心、工作台、编辑器扩展动作、创建应用，以及它们依赖的 V3 应用运行时。本文说明升级时数据怎样变化、出问题时按什么顺序回退。

## 数据变化一览

| 数据 | 位置 | 1.6.0 的变化 |
| --- | --- | --- |
| 数据库结构 | 服务器 SQLite | 扩展平台（Phase 0–5）**没有**新增表或迁移。1.6.0 其他功能（迁移中心）新增 5 个迁移 |
| 插件注册、权限、执行记录 | `plugin_registry`、`plugin_permissions`、`plugin_executions` | 沿用已有表。编辑器动作的执行记录不保存选区正文 |
| V3 应用与卡片的数据 | `plugin_storage` | 沿用已有表（1.5.5 已存在） |
| 个人应用与版本历史 | `personal_studio_apps`、`personal_studio_app_versions` | 表在 1.5.5 已存在。1.5.5 时代没有历史版本的应用，打开时自动补齐 |
| 插件安装包 | 数据目录 `plugins/installed` | 不变 |
| 工作台布局、侧栏固定、“添加到工作台”交接 | 浏览器 / 桌面端 localStorage | 新增的本地数据，按服务器、账号、工作区（布局还按屏幕尺寸）分开保存，不上传服务器 |

v1.5.5 已带有个人应用的数据库表，但没有 V3 应用运行时、工作台和扩展中心界面。1.6.0 是这些功能第一次正式提供。

## 升级（1.5.5 → 1.6.0）

- **备份**：升级前按现有流程做完整备份（Docker 在线更新会自动备份，见 [Docker 在线更新](../docker-online-update.md)）。
- **数据迁移**：扩展平台没有需要执行的数据迁移。
- **升级后的默认状态**：
  - V1、V2 插件照常运行；
  - V3 应用页面、工作台插件卡片、插件数据默认开启，资源检查器默认关闭；
  - 编辑器扩展动作默认关闭，要用时由管理员开启；
  - 扩展中心、工作台、创建应用没有开关，在 Web 和桌面端直接可用。
- **桌面客户端**：需要和服务器一起升级到 1.6.0，V3 页面才能在桌面端显示。旧版桌面客户端连接 1.6.0 服务器时，V3 页面仍是空白，与 1.5.x 相同。

## 功能级回滚（推荐）

出问题时，优先用环境变量关闭对应功能。这种方式不改数据，也不需要恢复备份；重新开启后，数据和布局都会回来。修改后重启服务生效。

| 关闭什么 | 设置 | 效果 |
| --- | --- | --- |
| 编辑器扩展动作 | 删除 `NOWEN_EDITOR_ACTIONS` 或设为 `0` | 菜单消失；`/contributions` 不再返回动作，执行接口返回 403；含编辑器动作的包不能再安装；已装插件和数据保留 |
| 资源检查器 | 不设 `NOWEN_EXTENSION_V3_INSPECTORS`（默认关闭） | 不出现检查器入口 |
| 工作台插件卡片 | `NOWEN_EXTENSION_V3_DASHBOARD_WIDGETS=0` | 插件卡片显示为休眠占位；内置卡片和个人应用卡片不受影响 |
| V3 应用页面（含卡片和检查器） | `NOWEN_EXTENSION_V3_APP_PAGES=0` | 应用列表为空，活动会话被拒绝；不能再安装 V3 应用 |
| 插件结构化数据接口 | `NOWEN_EXTENSION_V3_PLUGIN_DATA=0` | 数据接口被拒绝，数据保留 |
| 全部 V3 能力 | `NOWEN_EXTENSION_V3_CORE=0`（也可以显式设置 `NOWEN_EXTENSIONS_V21=0`） | 上述功能全部关闭 |

扩展中心本身没有开关。管理员的高级能力（来源与公钥、运行时策略、更新与回滚、开发者模式、调试与执行日志、本地安装包）在「设置 › 扩展管理」。

## 插件级回滚

- **停用**：插件的菜单、页面和卡片立即消失，数据保留。重新启用即可恢复。
- **卸载**：选「卸载并保留数据」，重新安装同一个插件后数据还在。「删除数据并卸载」会删除所有用户和工作区中该插件的数据，无法撤销。
- **更新失败**：自动恢复到原版本。中断的更新在服务重启后，会收敛到稳定、试运行或安全失败三种状态之一（见 `plugin-update-recovery-matrix` 用例）。
- **备份恢复后**：所有插件进入隔离状态，授权清零，需要管理员逐个审核后再启用。这是现有的安全策略。

## 版本降级（1.6.0 → 1.5.5）

**不能直接降级。**

- 1.6.0 新增了数据库迁移。1.5.5 启动时，数据库版本检查发现库比程序新，会拒绝启动（`DatabaseUpgradeRequiredError`），这是为了防止数据损坏。
- 确实要回到 1.5.5，只能停止服务，恢复**升级前**的完整备份。升级之后新写入的数据都会丢失。
- 动手之前，先把当前完整的数据目录另外备份一份。
- 恢复步骤和注意事项见 [Docker 在线更新 · 回滚边界](../docker-online-update.md#回滚边界)。

降级到 1.5.5 后：

- 工作台布局等本地数据不会被读取（1.5.5 没有这些功能），也不会影响其他功能；
- 恢复备份后，插件授权按上面的规则清零。

## Phase 5 的修改与回退

Phase 5 改了两处安全相关的行为：

1. **插件页面的 `frame-ancestors`**：只有 `platform=desktop` 的会话，其一次性文档才允许被 `file:` 页面嵌入。Web 会话保持 `'self'` 加 `X-Frame-Options: SAMEORIGIN`。
2. **Electron 主进程**：拦截插件 iframe 自己发起的跳转。

如果这两处改动引起问题：

- 回退第 1 点，桌面端 V3 页面会恢复空白，Web 端不受影响；
- **不要单独回退第 2 点**。没有它，桌面端插件页面可以把自己的 iframe 导航到外部网址，带出数据。
